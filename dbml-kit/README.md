# dbml-kit

> DBML 스키마를 비개발자에게 설명하고, 기획서와의 빈틈을 짚고, 개발자 확인 질문을 뽑고, Mermaid ERD로 렌더링하는 네 스킬 패키지. 비개발자가 .dbml을 스스로 이해하고 개발자와 정확히 소통하게 만든다.

- Version: `0.3.0`
- License: MIT
- Author: 정인권 (`developjik@colosseum.kr`)
- plugin-eval (정적): plugin 100/100, 각 skill 100/100, fail/warn 0건, 개선사항 0건 (상세는 references/로 이연해 invoke/trigger 토큰 moderate 유지)

## Skills

| 스킬 | 트리거 | 입력 | 산출물 |
|---|---|---|---|
| `dbml-explain` | `.dbml` 파일/코드블록이 대화에 등장, "이 스키마 설명해줘", "PM에게 DB 설명", "비개발자 설명" 같은 요청 | DBML 텍스트 (SQL DDL 아님) | 한 줄 요약 → 핵심 엔티티 → 관계 → enum → 시나리오 예시 → 누락/모호 지점 |
| `dbml-spec-diff` | DBML + PRD/기획서 둘 다 대화에 존재, "기획서랑 DBML 다른 부분", "스펙대로 됐는지", "find gaps PRD schema" | DBML 텍스트 + 기획 문서 | 커버리지 매트릭스 → 누락 → 초과 → 의미 불일치 → cardinality 충돌 → P0/P1/P2 Top 3 |
| `dbml-to-mermaid` | DBML이 있고 "ERD 그려줘", "mermaid로", "Confluence에 붙일 다이어그램", planning-publish 직전 그림 필요 | DBML 텍스트 (+ 선택: TableGroup) | Mermaid `erDiagram` fenced 블록 + 범례 → 한국어 캡션 → 임베드 가이드 → 손실/주의 항목 |
| `dbml-questions` | DBML이 있고 "개발자에게 뭘 물어봐야 해?", "확인 질문 정리", "슬랙에 보낼 질문" | DBML 텍스트 (+ 선택: 기획서/explain·diff 결과) | 우선순위(P0/P1/P2)별 복붙용 확인 질문 묶음 (근거 식별자 + 추정 답 + Yes/No·객관식) |

스킬 자체 본문은 각 `skills/<name>/SKILL.md`에 있고, 트리거 description은 plugin-eval baseline에 맞춰 짧게 유지합니다. 공통 용어 풀이는 `skills/dbml-explain/references/glossary.md`에 단일 기준으로 둡니다.

## 워크플로우 (비개발자용)

`.dbml`을 막 받았을 때 무엇부터 할지 4단계 흐름입니다. 각 단계에서 말할 한국어 트리거 예시를 함께 적습니다.

```text
받음 → 1.이해 → 2.기획서 비교 → 3.개발자 질문 → 4.같은 그림 공유
       explain   spec-diff       questions       to-mermaid → Confluence
```

1. **스키마 이해**: "이 DBML 설명해줘" → `dbml-explain` (테이블/관계/enum을 비즈니스 언어로, 양방향 용어 사전 포함).
2. **기획서와 비교**: "기획서랑 다른 부분 짚어줘" → `dbml-spec-diff` (누락/초과/충돌 + 합의용 질문).
3. **개발자에게 질문**: "개발자에게 물어볼 질문 정리해줘" → `dbml-questions` (우선순위별 복붙용 질문 묶음). explain/spec-diff 산출물의 질문 섹션을 그대로 모아도 됩니다.
4. **같은 그림 공유**: "ERD 그려줘" → `dbml-to-mermaid` → Confluence/README에 붙여 개발자와 같은 화면을 보며 대화.

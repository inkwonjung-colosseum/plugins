# DBML 용어집 (비개발자용)

세 스킬([[dbml-explain]], [[dbml-spec-diff]], [[dbml-to-mermaid]])이 공유하는 단일 용어 풀이 기준이다.
같은 약어는 어느 스킬에서든 아래 풀이로 통일한다. **약어 단독 사용 금지 — 첫 등장 시 풀이를 붙인다.**

## 키/제약 약어

| 약어 | 비개발자 풀이 | 한 줄 의미 |
|---|---|---|
| `PK` | 고유 식별값 | 각 행(row)을 구분하는 유일한 번호/값. 절대 중복되지 않는다. |
| `FK` | 다른 표를 가리키는 연결 | 이 컬럼이 다른 테이블의 한 행을 가리킨다 (예: `orders.user_id` → 어떤 사용자인지). |
| `UK` | 중복 불가 값 | 같은 값이 두 번 들어올 수 없다 (예: 이메일은 한 사람당 하나). |

## 관계(cardinality) 표기

| 표기 | 풀이 | 예시 |
|---|---|---|
| `1:1` | 서로 하나씩 | 한 사용자에 프로필 하나, 그 반대도 하나. |
| `1:N` | 하나가 여럿을 가짐 | 한 사용자가 여러 주문을 가짐. |
| `N:M` | 양쪽 모두 여럿을 가짐 (중간 연결표가 둘을 이어줌) | 한 주문에 여러 상품, 한 상품은 여러 주문에 담김 → `order_items`가 잇는다. |

> `N:M`은 약어로 끝내지 말고 항상 **연결 테이블 비즈니스 문장**으로 풀어 설명한다.

## DBML `Ref` 표기 → 방향 풀이

DBML 관계 줄(`Ref:` 또는 컬럼 inline `[ref: ...]`)의 화살표 기호를 아래로 통일해 읽는다. **화살표 방향에 헷갈리지 말 것 — 항상 "하나 쪽 → 여럿 쪽" 비즈니스 문장으로 바꿔 말한다.**

| DBML 기호 | 관계 | 비개발자 풀이 예시 |
|---|---|---|
| `Ref: orders.user_id > users.id` (`>`) | N:1 | "주문 여러 건이 사용자 한 명을 가리킨다 = 한 사용자가 여러 주문을 가짐." |
| `Ref: users.id < orders.user_id` (`<`) | 1:N | "한 사용자가 여러 주문을 가짐" (위와 같은 관계, 표기 방향만 반대). |
| `Ref: users.id - profiles.user_id` (`-`) | 1:1 | "사용자 한 명에 프로필 하나, 그 반대도 하나." |
| `Ref: orders.id <> products.id` (`<>`) | N:M | "연결 테이블이 둘을 이어준다" — 반드시 연결 테이블 문장으로 풀이. |

> `>`와 `<`는 **같은 관계를 양방향으로 적은 것**일 뿐이다. 비개발자에게는 화살표가 아니라 "누가 하나이고 누가 여럿인지"만 말한다.

## 표기/식별자

| 용어 | 풀이 |
|---|---|
| `snake_case` | 영문 소문자와 밑줄(`_`)로 쓴 식별자 표기 (예: `user_id`). 코드에서 표/컬럼 이름을 적는 방식. |
| `_id` 접미사 | 보통 다른 표를 가리키는 연결 컬럼 신호 (= FK). |
| `enum` | 정해진 값 중 하나만 들어가는 분류값 (예: 주문 상태 = `pending`/`paid`/`shipped`). |

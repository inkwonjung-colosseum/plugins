# Output Contract

`planning-format` 출력 포맷·헤더 줄 형식·저장 처리·체크리스트·출처/누락 요약·하단 상세 추적·`## 출처` list URL deep link·parser boundary 형식. SKILL.md Step 8~9 진입 시 1회 Read 적재.

0.2.14 우선 규칙: 최종 응답은 실행 로그가 아니라 산출물이다. `planning-format`은 옵션이 없으면 저장을 실행한다. 기본 저장 성공 출력은 헤더 요약 -> `## 저장 파일` -> `## 체크해야 할 항목` 순서이며, 정책서·기능설계서 전문을 화면에 반복 출력하지 않는다. `--no-save`와 저장 실패 fallback에서만 정책서·기능설계서 전문을 화면에 펼친다. 신규 public 출력에서 상단 요약/결정 projection heading을 쓰지 않는다.

0.2.11 우선 규칙: 사용자-facing 출력과 저장 파일은 clean display를 사용한다. 섹션 기호를 출력하지 말고 `정책서 5.1`, `기능설계서 7`, `입력 제외 섹션`, `보조 표`처럼 사람이 읽는 위치 표기로 쓴다. 원문 직접 인용 안에 기호가 포함된 경우만 예외다.

0.2.10~0.2.13 legacy 입력은 parser가 읽기 호환한다. 다만 0.2.14 신규 public 출력은 하단 checklist를 실행 projection으로 사용한다.

## 1. 출력 블록 순서

### 0.2.14 기본 저장 성공 출력

```markdown
# [기능명]

- 입력: [사람이 읽는 요약]
- 산출물: 정책서, 기능설계서
- 검증: 확인 필요 N건, 문서 보강 M건, 출처 누락 K건 / 확인 필요 없음
- 저장: planning/[안전기능명]--YYYY-MM-DD-HHMMSS/

---

## 저장 파일

- 정책서: planning/[안전기능명]--YYYY-MM-DD-HHMMSS/[안전기능명]_정책서.md
- 기능설계서: planning/[안전기능명]--YYYY-MM-DD-HHMMSS/[안전기능명]_기능설계서.md

---

## 체크해야 할 항목

[결정 필요 / 문서 보강 필요 / 출처·누락 참고]
```

### 0.2.14 --no-save 화면 only 출력

```markdown
# [기능명]

- 입력: [사람이 읽는 요약]
- 산출물: 정책서, 기능설계서
- 검증: 확인 필요 N건, 문서 보강 M건, 출처 누락 K건 / 확인 필요 없음
- 저장: 없음 (--no-save)

---

## 정책서

[정책서 본문 - 일반 Markdown]

---

## 기능설계서

[기능설계서 본문 - 일반 Markdown]

---

## 체크해야 할 항목

[결정 필요 / 문서 보강 필요 / 출처·누락 참고]
```

### 0.2.14 저장 실패 fallback 출력

```markdown
# [기능명]

- 입력: [사람이 읽는 요약]
- 산출물: 정책서, 기능설계서
- 검증: 확인 필요 N건, 문서 보강 M건, 출처 누락 K건 / 확인 필요 없음
- 저장: 실패 - [사람이 읽는 사유]

---

## 정책서

[정책서 본문 - 일반 Markdown]

---

## 기능설계서

[기능설계서 본문 - 일반 Markdown]

---

## 체크해야 할 항목

[결정 필요 / 문서 보강 필요 / 출처·누락 참고]

---

## 저장 실패 상세

- 실패 단계: [folder/write/verify 등]
- 대상 경로: planning/[안전기능명]--YYYY-MM-DD-HHMMSS/
- 남은 파일 또는 폴더: [있음/없음/확인 불가]
```

조건부 하단 섹션:

```markdown
## 출처/누락 요약

[source type별 요약 + 실패/본문 미사용/입력 제외 high-signal 항목]

## 상세 추적

[조건 충족 시에만 full 출처표 / full 입력 제외 5필드 list / 연결 맵 / fetch status 세부]
```

규칙:

- 최종 출력은 반드시 `# [기능명]`으로 시작한다.
- 최종 출력 앞에 fetch 진행 문장, 도구 fallback 설명, "변환을 시작합니다" 같은 로그 문장을 쓰지 않는다.
- 기본 저장 성공 출력의 top-level H2는 `## 저장 파일`, `## 체크해야 할 항목`뿐이다.
- 기본 저장 성공 출력에서는 `## 저장 파일`이 첫 H2다.
- 기본 저장 성공 출력에는 `## 정책서`, `## 기능설계서` 본문 섹션을 출력하지 않는다. 전문은 저장 파일을 기준으로 확인한다.
- `--no-save` 출력과 저장 실패 fallback 출력에서는 `## 정책서`가 첫 H2이며, `## 기능설계서`와 `## 체크해야 할 항목`을 이어서 출력한다.
- 저장 실패 fallback 출력에서만 `## 저장 실패 상세`를 출력한다.
- 정책서와 기능설계서 본문은 저장 실패 또는 `--no-save` 화면에서 출처·누락·검증 상세보다 먼저 나온다.
- 화면 본문의 정책서와 기능설계서 전체를 코드 펜스로 감싸지 않는다.
- 같은 정책서·기능설계서 본문을 읽기용 일반 Markdown과 코드 펜스 원문 블록으로 중복 출력하지 않는다.
- `--no-self-review`면 상단 검증 줄은 `- 검증: 생략 (--no-self-review)`이고 checklist에는 자체검증 발견 없이 입력 제외·출처 기반 확인 사항만 남긴다.
- self-review를 실행했고 사용자 확인 필요와 출시 전 해결 필요 항목이 모두 없으면 상단 검증 줄에 `확인 필요 없음`을 명시한다.
- `저장: 화면 only` 표현은 쓰지 않는다. 저장하지 않는 실행은 `- 저장: 없음 (--no-save)`로 쓴다.
- `## 출처/누락 요약`과 `## 상세 추적`은 기본 저장 성공 출력에서는 top-level H2로 출력하지 않는다. 핵심 출처·누락 정보는 `## 체크해야 할 항목 > 출처/누락 참고`에 둔다.
- `--no-save` 또는 저장 실패 fallback에서는 fetch 실패, 원문 정의 부재, 입력 제외 high-signal 항목이 있을 때 `## 출처/누락 요약`을 출력할 수 있다.
- `--no-save` 또는 저장 실패 fallback에서 full 출처표, full 입력 제외 목록, parser warning, connector 실패, 연결 맵이 필요한 경우에만 `## 상세 추적`을 출력할 수 있다.
- 반영 위치, 대상, 위치, 처리, 설명 필드에는 clean display를 사용한다. 예: `정책서 5.1 / 기능설계서 7`, `출처 1의 9.1`, `입력 제외 섹션`.

### 1.1 체크해야 할 항목

`## 체크해야 할 항목`은 저장 파일 또는 `--no-save` 화면 본문을 확인한 뒤 처리할 후속 checklist다.

기본 subsection:

1. `결정 필요`
2. `문서 보강 필요`
3. `출처/누락 참고`

규칙:

- subsection 순서는 `결정 필요` -> `문서 보강 필요` -> `출처/누락 참고`다.
- 항목이 없는 subsection은 `없음`으로 쓴다.
- `결정 필요자`는 출력하지 않는다. 특정 외부 승인 주체가 원문에 명시된 경우에만 `승인/확인 주체`를 예외적으로 추가한다.
- `확인할 것`은 사용자가 답해야 하는 판단을 한 문장으로 쓴다.
- `이유`는 원문 TBD, 확정 시 재정의, fetch 실패, 충돌 후보, 용어 혼재 등 핵심 근거를 한 줄로 쓴다.
- `반영 위치`는 clean display를 사용한다. 예: `정책서 세부 규칙`, `기능설계서 예외와 메시지`.
- full 검증문, Given/When/Then, full source URL, connector status code 전문은 쓰지 않는다.

예:

```markdown
## 체크해야 할 항목

### 결정 필요

1. Refurbish 완료 후 재고 속성
   - 확인할 것: 완료 후 가용 재고로 전환할지 보류 재고로 둘지 정해야 합니다.
   - 이유: 원문에 `[TBD]`가 남아 있어 재고 상태 전이가 확정되지 않았습니다.
   - 반영 위치: 정책서 상태 처리 기준, 기능설계서 상태 전환

### 문서 보강 필요

1. Figma 사용자 흐름
   - 이유: Figma 링크 본문 확인 실패로 화면 흐름 근거가 비어 있습니다.
   - 반영 위치: 기능설계서 사용자 흐름

### 출처/누락 참고

- 추가 출처 1건은 인증 필요로 본문에 합류하지 못했습니다.
```

## 2. 출력 아티팩트 레이어

한 번의 응답 안에서도 다음 레이어를 구분한다.

| 레이어 | 목적 | 출력/저장 위치 | 주요 규칙 |
|---|---|---|---|
| canonical 본문 | 정책서·기능설계서의 의미 기준 | 메모리 내부 + 저장 파일 + `--no-save`/실패 fallback 화면 | 정책 값·상태·권한·임계값·문구 의미를 보존한다. |
| 저장 파일 | 원문 Markdown으로 재사용 가능한 산출물 | `planning/[안전기능명]--YYYY-MM-DD-HHMMSS/` | 정책서 1개 + 기능설계서 1개. canonical Markdown 구조를 우선 보존. |
| 저장 성공 화면 | 저장 결과 handoff | 기본 응답의 `## 저장 파일` | 저장 파일 path 2개와 후속 checklist만 보여준다. |
| 화면 렌더링 | 저장하지 않거나 저장 실패한 경우 결과 손실 방지 | `--no-save`와 저장 실패 fallback의 `## 정책서`, `## 기능설계서` | 코드 펜스 wrapper 제거, 넓은 표 분해, 긴 셀 bullet화 같은 표시 변환 가능. 의미 변경 금지. |
| 체크해야 할 항목 | 결정·보강·출처 누락 후속 처리 | 모든 public 출력의 하단 | 사용자 판단과 문서 보강만 압축한다. 원시 trace와 connector 세부는 금지. |
| 검증 피드백 | self-review 발견과 수정 제안 | 내부 분류 + checklist + 조건부 상세 추적 | 사용자 승인 전 의미 수정 금지. 위치·문제·영향·제안·확인 필요 여부를 보존한다. |
| 상세 추적 | 출처·입력 제외·fetch status | `--no-save` 또는 실패 fallback의 하단 `## 상세 추적` | 일반 검토자가 매번 필수로 읽는 영역이 아니어야 한다. |

정확한 정책서·기능설계서 원문이 필요하면 저장 성공 시 저장 파일을 기준으로 삼는다. `--no-save`와 저장 실패 fallback은 화면에 나온 본문을 기준으로 삼는다.

## 3. 헤더 줄 형식

### 3.1 입력 줄

기본 화면은 내부 도구 경로보다 사람이 읽는 요약을 우선한다.

```markdown
- 입력: 직접 입력
- 입력: 파일 2개, 이미지 1개
- 입력: URL 1개, 추가 출처 4개
- 입력: 디렉터리 텍스트 5개, 이미지 2개, 추출 URL 3개
```

도구 경로(`via Atlassian MCP`, `via Google Drive connector`)는 기본 헤더에 쓰지 않는다. 실패나 인증 문제가 있을 때만 `출처/누락 참고` 또는 `## 출처/누락 요약` 비고에 짧게 남긴다.

### 3.2 검증 줄

| 케이스 | 출력 |
|---|---|
| self-review 실행 + 피드백 0건 | `- 검증: 확인 필요 없음` |
| self-review 실행 + 피드백 있음 | `- 검증: 확인 필요 N건, 문서 보강 M건[, 출처 누락 K건]` |
| `--no-self-review` | `- 검증: 생략 (--no-self-review)` |

사용자 확인 필요 항목이 있으면 checklist의 `결정 필요`에 두고, 문서 작업은 `문서 보강 필요`에 둔다.

### 3.3 저장 줄

| 케이스 | 출력 |
|---|---|
| 기본 저장 성공 | `- 저장: planning/[안전기능명]--YYYY-MM-DD-HHMMSS/` |
| 같은 초 collision | `- 저장: planning/[안전기능명]--YYYY-MM-DD-HHMMSS--2/` |
| `--no-save` | `- 저장: 없음 (--no-save)` |
| 저장 실패 | `- 저장: 실패 - <사유>` |

저장 실패는 호출 종료 사유가 아니다. 본문 변환·검증 결과는 화면에 그대로 출력하고, 실패 상세를 하단에 남긴다.

## 4. 검증 피드백

self-review 발견은 기본 public 출력에서 별도 top-level 필수 섹션이 아니다. 발견은 다음 방식으로 재배치한다.

| 발견 성격 | 기본 위치 |
|---|---|
| 사용자 판단 필요 | `## 체크해야 할 항목 > 결정 필요` |
| 문서 작업 필요 | `## 체크해야 할 항목 > 문서 보강 필요` |
| 출처 실패·원문 정의 부재·입력 제외 high-signal | `## 체크해야 할 항목 > 출처/누락 참고` 또는 관련 checklist 항목의 `이유` |
| 원시 F* 상세, 수정 제안, 연결 맵 | 조건부 `## 상세 추적` |

규칙:

- 의미 변경이 필요한 F2/F3/F4/F6 발견은 정책서·기능설계서 canonical 본문에 자동 반영하지 않는다.
- 사용자 승인 전에는 `수정 제안 가능`과 `사용자/외부 결정 필요` 항목을 본문에 조용히 반영하지 않는다.
- 기계적 안정화와 화면 전용 표시 변환은 의미 변경 없이 적용 가능하지만, 보정 사실은 checklist 또는 상세 추적에 남긴다.
- F* ID는 원시 추적이 필요할 때 상세 추적에만 보존한다. 기본 checklist는 자연어 항목명을 우선한다.

## 5. 출처/누락 요약

기본 저장 성공 출력은 full 출처표를 펼치지 않는다. 결과 신뢰도에 영향을 주는 실패·인증 문제·본문 미사용 출처만 `## 체크해야 할 항목 > 출처/누락 참고`에 남긴다.

`--no-save` 또는 저장 실패 fallback에서 `## 출처/누락 요약`이 필요한 경우 count와 결과 영향 항목만 압축한다.

```markdown
## 출처/누락 요약

- 원본 입력: URL 1개
- 추가 출처: 성공 4개 / 실패 1개
- 결과 영향: Figma 사용자 흐름 1건 본문 확인 실패
- 입력 제외: 범위 외 12건 / 구조 변환 3건 / fetch 실패 1건
```

### 5.1 출처 list URL = deep link 형식

하단 `## 상세 추적`의 full `## 출처` 표 행 URL은 anchor 지원 source에서 deep link 형식을 저장한다.

| Source | URL 형식 | 비고 |
|---|---|---|
| WebFetch HTML | `URL#<heading-id>` (있으면) | `<h*> id="..."` parsing. 없으면 page-level. |
| Confluence | `URL#<heading-id>` | `connector-routing.md` 11.1 |
| Google Docs | `URL#heading=h.<digest>` | 11.2 |
| Google Slides | `URL#slide=id.<id>` | 11.3 |
| Notion | `URL#<block-id>` | 11.4 |
| Google Sheets | `URL#gid=<id>&range=<cell>` | 기존 gid/range 처리 |
| Figma | `URL?node-id=<id>` | URL query 그대로 |
| Slack | thread 영구링크 | URL 자체 |
| Jira | page-level (`#comment-<id>` 가능) | summary·description 단위는 anchor 없음 |

추출 실패·미지원 source = page-level URL fallback. 표 행 URL = 입력 제외 섹션 위치 필드 markdown link URL과 동일.

## 6. 입력 제외 요약 규칙

기본 저장 성공 출력은 개별 제외 항목을 펼치지 않는다. 결과 영향이 있는 항목만 checklist로 올린다. `--no-save` 또는 저장 실패 fallback에서 별도 요약이 필요해도 신규 public H2는 `## 출처/누락 요약` 하나로 합친다.

| 조건 | 기본 출력 처리 |
|---|---|
| `fetch 실패` | 핵심 흐름에 영향 있으면 `문서 보강 필요`, 그 외 `출처/누락 참고` |
| `충돌 후보` | 선택/미선택 상태를 `결정 필요`의 이유에 표시 |
| `원문 정의 부재` | 정책/기능 판단을 막으면 `결정 필요`, 그 외 `출처/누락 참고` |
| `라벨 미매핑` | 문서 본문 반영 누락 가능성이 있으면 `문서 보강 필요` |

full 5필드 항목 list는 7 조건 충족 시 하단 `## 상세 추적`에 둔다. 5필드 형식은 `exclusion-rules.md` 4를 유지한다.

## 7. 상세 추적

새 옵션을 추가하지 않는다. 기존 출력에 포함되던 상세 추적 정보는 조건 충족 시 하단으로 이동한다.

`## 상세 추적` 출력 조건:

| 조건 | 처리 |
|---|---|
| fetch 실패, 인증 실패, 본문 미사용 출처가 1건 이상이고 원시 행 확인이 필요함 | full `## 출처` 표 포함 |
| `충돌 후보`, `원문 정의 부재`, `라벨 미매핑`이 1건 이상이고 checklist만으로 근거 확인이 부족함 | full `## 입력 제외 항목` 5필드 항목 포함 |
| checklist 항목이 원시 F* 또는 입력 제외 항목을 접어 표시함 | `### 체크리스트 연결 맵` 포함 |
| 기계적 안정화 또는 화면 전용 표시 변환이 발생 | 보정 사실과 위치 포함 |
| 모두 성공이고 제외/발견이 checklist로 충분 | 상세 추적 생략 가능 |

상세 추적을 출력하더라도 기본 상단보다 먼저 나오면 안 된다.

### 7.1 Full 출처 표

```markdown
### 출처

원본 입력: <직접 입력 / 파일 N개 / 디렉터리 텍스트 N개 / URL M개 / 이미지 I개>
재귀 본문 가져오기: 성공 N개 / 실패 K개 (cap 없음)

| # | depth | 출처 종류 | URL/경로 또는 위치 | 상태 | 본문 사용 |
|---|---:|---|---|---|---|
| 0 | - | 원본 | 직접 입력 / 파일 / 디렉터리 / - | - | O (원본) |
| 1 | 0 | 인자 URL | <Confluence URL>#취소-정책 | 200 (via Atlassian MCP) | O |
| 2 | 1 | 자식 URL | <Sheets URL>#gid=0&range=C13 (출처: [#1] line N) | 200 (via Google Drive connector - read_file_content) | O |
```

### 7.2 Full 입력 제외 항목

```markdown
### 입력 제외 항목

1. [한 줄 제목]
   - 카테고리: [11종 중 하나]
   - 위치: [출처 N](URL#anchor) [부연 plain text]
   - 인용: "[입력 원문 <=80자]"
   - 처리: [exclusion-rules.md 5 처리 줄]
   - 설명: [왜 본문에 안 넣었는지 한 줄]
```

### 7.3 체크리스트 연결 맵

```markdown
### 체크리스트 연결 맵

- 결정 필요 1 -> F5-1
- 문서 보강 필요 1 -> 입력 제외 3
```

기본 checklist에서는 원시 F* ID를 접어 표시하고, 이 mapping과 상세 추적에서 원본을 확인할 수 있게 한다.

## 8. 저장 처리

### 8.1 저장 경로

저장은 default-on이다. 옵션이 없어도 현재 작업 디렉터리 기준 `planning/` 아래에 저장한다. `--save`는 0.2.x 호환용 no-op alias이며 기본 저장 동작과 동일하다. 저장하지 않는 화면 only 실행은 `--no-save`로만 명시한다.

```text
planning/[안전기능명]--YYYY-MM-DD-HHMMSS/
  [안전기능명]_정책서.md
  [안전기능명]_기능설계서.md
```

규칙:

- default-on 저장을 실행한다. `--no-save`가 있을 때만 저장하지 않는다.
- 숨김 폴더인 `.planning-kit/`은 신규 저장 경로로 사용하지 않는다.
- 저장 파일 개수는 정책서 1개 + 기능설계서 1개다.
- 저장 파일에는 `## 체크해야 할 항목`, `## 출처/누락 요약`, `## 상세 추적`, `## 저장 실패 상세`를 쓰지 않는다.
- 저장 파일은 화면용 카드/필드 목록이 아니라 canonical Markdown 구조를 우선 보존한다.
- 저장 폴더는 review 대상 입력이 될 수 있다.
- 저장 폴더와 그 하위 파일은 기준 문서 묶음 근거가 될 수 없다.
- `planning/` 폴더는 생성 산출물·작업 초안·review target의 영역이며 기준 문서 저장소가 아니다.

### 8.2 기능명 안전화

1. NFC normalize.
2. 경로 분리자(`/`, `\`), 컨트롤 문자, 파일명 금지 문자(`:`, `*`, `?`, `"`, `<`, `>`, `|`)를 `-`로 바꾼다.
3. 양끝 공백·마침표를 제거한다.
4. 결과가 비면 `untitled`를 사용한다.
5. 80자를 넘으면 Unicode grapheme cluster 경계에서 80자 이하로 자르고, 자른 뒤 양끝 공백·마침표를 다시 제거한다.
6. Windows 예약 basename(`CON`, `PRN`, `AUX`, `NUL`, `COM1`~`COM9`, `LPT1`~`LPT9`)은 대소문자 무관으로 금지하고 뒤에 `-file`을 붙인다.

### 8.3 Timestamp와 collision

- timestamp는 사용자 locale 기준 현재 시각을 `YYYY-MM-DD-HHMMSS`로 기록한다.
- 같은 초에 폴더명이 충돌하면 폴더명 끝에 `--2`, `--3` suffix를 붙인다.
- 기존 파일을 덮어쓰지 않는다.

### 8.4 저장 실패 fallback

저장 실패 fallback은 저장 처리 중 파일 쓰기, 검증, rename, 최종 파일 존재 확인 중 하나라도 실패했을 때 사용한다.

규칙:

- 정책서·기능설계서 전문을 화면에 출력한다.
- `## 정책서`가 첫 H2다.
- `## 체크해야 할 항목` 뒤에 `## 저장 실패 상세`를 출력한다.
- 실패 단계, 대상 경로, 남은 파일 또는 폴더 상태를 사람이 읽을 수 있게 남긴다.
- 실패한 저장 폴더를 성공 저장 출력처럼 `## 저장 파일` handoff로 표시하지 않는다.

## 9. Readable Projection Parser

`planning-review`와 downstream parser는 0.2.14 기본 저장 성공 화면을 본문 projection으로 취급하지 않는다. 저장 파일 경로 handoff 또는 `--no-save`/저장 실패 fallback 본문을 사용한다.

1. `## 저장 파일`이 있고 `## 정책서`와 `## 기능설계서` 본문이 없으면 저장 파일 handoff 후보로만 본다.
2. 저장 경로가 있더라도 `## 정책서`와 `## 기능설계서` 본문이 함께 있으면 본문을 우선한다. 이는 `--no-save` 또는 저장 실패 fallback의 결과 손실 방지 경로다.
3. wrapper heading은 줄 시작의 정확한 H2만 인정한다. CRLF는 LF로 정규화하고, 파일 첫 BOM은 무시하며, trailing whitespace는 제거한다. leading space, closing hash, H3 이하 heading은 wrapper로 인정하지 않는다.
4. fenced code block 안, blockquote 안, 리스트 하위의 wrapper 문자열은 wrapper heading으로 보지 않는다. fenced code block은 backtick fence와 tilde fence를 모두 포함한다.
5. 닫히지 않은 fenced code block이 있으면 이후 heading은 wrapper로 인정하지 않고 `readable projection boundary ambiguous` warning을 남긴다.
6. 정책서 본문은 첫 `## 정책서` wrapper heading 다음 줄에서 시작해 다음 wrapper heading 중 먼저 등장하는 `## 기능설계서`, `## 체크해야 할 항목`, `## 출처/누락 요약`, `## 상세 추적`, `## 저장 실패 상세`, `## 결론`, `## 검토 결과`, legacy `## 출처 요약`, legacy `## 입력 제외 요약`, EOF까지다.
7. 기능설계서 본문은 첫 `## 기능설계서` wrapper heading 다음 줄에서 시작해 다음 wrapper heading 중 먼저 등장하는 `## 체크해야 할 항목`, `## 출처/누락 요약`, `## 상세 추적`, `## 저장 실패 상세`, `## 결론`, `## 검토 결과`, legacy `## 출처 요약`, legacy `## 입력 제외 요약`, EOF까지다.
8. `## 저장 파일`, `## 체크해야 할 항목`, `## 출처/누락 요약`, `## 상세 추적`, `## 저장 실패 상세`, `## 결론`, `## 검토 결과`, legacy `## 출처 요약`, legacy `## 입력 제외 요약`은 정책서·기능설계서 본문 경계로 사용한다.
9. 생성된 정책서·기능설계서 본문 안에서는 위 wrapper heading을 최상위 H2로 쓰지 않는다. 본문에서 같은 의미의 heading이 필요하면 H3 이하 하위 heading을 사용한다.
10. 0.2.13 이하 산출물처럼 legacy metadata heading이 있는 입력은 읽기 호환하되, 신규 출력 목표로 재생성하지 않는다.
11. 경계가 둘 이상으로 해석되거나 한쪽 본문을 확정할 수 없으면 임의 병합하지 않는다.

## 10. 사용자-facing 용어

기본 상단 출력은 내부 도구 용어보다 한국어 업무 용어를 우선한다.

| 내부/기술 용어 | 기본 화면 권장 표기 |
|---|---|
| `Action Backlog` / `액션 Backlog` | `문서 보강 필요` 또는 `후속 작업` |
| `D1` | `결정 필요 1` |
| `A1` | `문서 보강 필요 1` |
| `T1` | `출시 전 해결 필요 1` |
| `P0` | `차단` |
| `P1` | `중요` |
| `P2` | `권고` |
| `placeholder` | `본문 없는 문서` |
| `SSOT corpus` | `기준 문서 묶음` |
| `SSOT token 폴더` | ``SSOT` 표시가 있는 기준 문서 폴더` |
| `raw markdown` | `붙여 넣은 Markdown 원문` |
| `fetch` | `본문 가져오기` 또는 `외부 본문 확인` |
| `deps` | `영향 분석` |
| `AC Blocker` | `구현/QA 차단` |
| `connector fallback` | 기본 상단 노출 금지. 실패/인증 문제가 있을 때만 출처/누락 참고나 출처/누락 요약 비고에 짧게 표시 |

상세 추적 섹션에서는 기존 parser 호환을 위해 일부 기술 용어를 병기할 수 있다.

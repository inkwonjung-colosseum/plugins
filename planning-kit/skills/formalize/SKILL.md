# formalize

기획 초안을 받아 **정책서 + 기능설계서 두 본문**으로 변환하고, **같은 응답에서 자동 리뷰**까지 한 번에 출력하는 단일 스킬이다. 산출물은 **로컬 파일로 저장하지 않는다**. 모두 화면 output(응답 markdown)으로만 반환한다.

호출 한 번 = 변환 본문 2개 + 입력 제외 항목 + 리뷰 결과. 사용자는 응답 markdown을 보고 직접 복사·붙여넣는다.

## 인자

- 위치 인자 1개 (필수): 기획 초안 텍스트, 파일 경로, 디렉터리 경로 중 하나.
- `--ssot-include <glob>` (optional): 리뷰 SSOT corpus glob. default = 프로젝트 폴더 안 모든 `*.md` (노이즈 폴더 자동 제외).
- `--no-review` (optional): 리뷰 단계 건너뜀. 변환 본문만 출력.

## 동작 시퀀스

### Step 1: 입력 dispatch

1. 첫 인자가 존재하는 파일 경로면 `Read`로 읽어 본문 확보. UTF-8 텍스트가 아니면 무시.
2. 디렉터리 경로면 `find <dir> -type f -name '*.md' -o -name '*.txt' -o -name '*.markdown'` 등으로 텍스트 파일 목록을 만들고, 각 파일을 `Read`로 읽어 한 본문으로 통합. 노이즈 폴더(`.git/`, `node_modules/`)는 제외.
3. 그 외(파일/디렉터리 아님)면 인자 텍스트 자체를 본문으로 본다.
4. 통합 본문이 literal 빈 문자열·whitespace·0byte이거나, 입력 디렉터리에 텍스트 파일이 0개면 §빈 입력 sanity check로 점프.

### Step 2: 빈 입력 sanity check

통합 본문이 비어 있으면 다음 한 줄만 출력하고 종료:

```
입력 비어 있음. 기획 초안 텍스트 또는 경로를 인자로 주세요.
```

그 외 모든 입력은 **변환을 시도한다**. 근거 부족·범위 모호·짧은 메모도 변환 진행. 부족분은 [TBD]로 채우고, 라벨 매핑이 안 되는 조각은 입력 제외 추적에 기록한다.

### Step 3: 기능명 추출 + 입력 제외 추적 준비

1. 기능명 추출 (출력 헤더용). 안전기능명 정규화·파일명 정규화는 안 한다 (저장 안 함).
2. 선택 우선순위:
   1. 입력에 명시된 주제 (예: `# 주문 취소`, `## 입고 기능`, `[기능명]: ...`).
   2. 단일 파일 입력이면 파일명 stem.
   3. 디렉터리 입력이면 디렉터리명.
   4. 본문에 반복 등장하는 제목.
   5. 첫 핵심 명사구.
3. 여러 기능 후보가 있으면 **1순위 1개만** 처리. 그 외 후보는 변환에서 제외하고 입력 제외 추적에 `다른 기능 후보` 사유로 기록.
4. 입력 제외 추적 list 초기화. Step 4 변환 중 라벨 매핑 안 되거나 중복인 조각이 발생할 때마다 항목을 추가한다.

### Step 4: 두 템플릿 변환 (항상 실행)

1. 두 템플릿을 병렬 `Read`:
   - `templates/기능설계서.md` (8 섹션: 개요·범위·사용자 흐름·화면과 입력·기능 동작·권한·예외·미결)
   - `templates/정책서.md` (10 섹션: 목적·적용 범위·용어·정책 원칙·세부 규칙·상태·역할·예외 승인·외부 연동·미결)
2. main이 같은 턴에서 두 본문을 직접 작성한다.
3. 라벨 매핑:
   - 화면·흐름·동작·입력 항목·권한·예외 메시지 → 기능설계서.
   - 규칙·조건·예외 승인·역할 책임·상태 전이·연동 정책 → 정책서.
4. 라벨 매핑이 어느 쪽도 안 되는 조각, 같은 내용이 다른 위치에 이미 들어간 조각, 단편적이라 [TBD]로도 못 채우는 조각은 입력 제외 추적으로 보낸다.
5. 근거가 부족한 셀은 inline `[TBD]`로 채운다. 빈 row·빈 섹션은 삭제 허용.
6. marker는 `[TBD]` 1종만 사용. `[미정]`/`[가정]`/`[확인 필요]`/`[충돌 후보]`/`해당 없음` 모두 사용 금지.
7. 작성 결과는 메모리에만 보관. **파일 저장 안 함** (`Write`·`mkdir`·`Bash` 저장 호출 없음).

### Step 5: 자동 리뷰 (`--no-review` 아닐 때)

1. `references/review-rules.md`를 `Read`로 읽어 2축 기준 확정.
2. 메모리의 두 본문 + 입력 본문 + SSOT corpus만 근거로 main이 단일 패스 점검.
3. **A. 본문 자체 품질 (Self-Review)**: 충실도·라벨 cross-bleed·용어 일관성·정책-기능 매핑·누락 핵심 정보. 기준은 `review-rules.md` §A 참조.
4. **B. SSOT 충돌**:
   - 변환 본문에서 키워드 추출 (기능명·도메인·역할·상태·정책 핵심어).
   - `--ssot-include` 인자가 있으면 해당 glob, 없으면 프로젝트 폴더 전체 `*.md` (`.git/`, `node_modules/` 자동 제외)에서 `grep -l` 또는 `rg -l`로 키워드 매칭.
   - 매칭 0건 → B축 `검증 대상 없음`. 출력에 `SSOT 매칭 파일 0개`로만 표시. 결과를 낮추지 않는다.
   - 매칭 ≥1건 → 매칭 file을 직접 `Read`. 변환 본문 확정 문장과 비교해 충돌 항목 list화.
5. 결과 결정:
   - 자체 품질 0건 + SSOT 충돌 0건 → `통과`.
   - 어느 한쪽이라도 ≥1건 → `발견 N건`. 카테고리별 발견 list 출력.

### Step 6: 통합 출력 (화면 output only)

§출력 포맷에 따라 **단일 응답 markdown** 1개 출력. 변환 본문 2개 + 입력 제외 항목(있을 때) + 리뷰 결과(없으면 `--no-review`)를 한 응답에 합친다.

## 출력 포맷

모든 출력은 응답 markdown. 정책서·기능설계서 본문은 ` ```markdown ... ``` ` 코드 펜스로 감싸 사용자가 통째로 복사할 수 있게 한다.

### 정상 (변환 + 리뷰)

응답 markdown 1개에 다음을 순서대로 합친다 (아래 템플릿은 docs 가독성용 4-backtick fence로 감싸져 있다 — 실제 응답에서는 4-backtick wrapper는 출력하지 않고 안쪽 본문만 출력한다):

````markdown
# [기능명]

- 입력 처리: [직접 입력 / 파일 N개 / 디렉터리 텍스트 N개]
- 미결 표기: [TBD] N개
- 입력 제외: N건 (0건이면 "없음")

---

## 정책서

```markdown
[정책서 본문 — 10 섹션 markdown 그대로]
```

---

## 기능설계서

```markdown
[기능설계서 본문 — 8 섹션 markdown 그대로]
```

---

## 입력 제외 항목

발견 사항 (≥1건일 때만 출력. 0건이면 이 섹션 통째로 생략):

1. [한 줄 제목]
   - 사유: [다른 기능 후보 / 라벨 미매핑 / 중복 / 근거 부족 무시 / 포맷 노이즈]
   - 위치: [파일명:라인 또는 "직접 입력"]
   - 인용: "[입력 원문 ≤80자]"
   - 설명: [왜 본문에 안 넣었는지 한 줄]

---

## 리뷰 결과: [통과 | 발견 N건]

- 자체 품질 발견: N건
- SSOT 충돌 발견: N건 (SSOT 매칭 파일 N개)

### 자체 품질 (Self-Review)

발견 사항 (≥1건일 때만):

1. [제목]
   - 카테고리: [충실도 / cross-bleed / 용어 일관성 / 정책-기능 매핑 / 누락]
   - 위치: [정책서/기능설계서 §섹션]
   - 근거: "[변환 본문 인용]"
   - 영향: [한 줄]
   - 제안: [최소 수정 또는 확인 조건]

### SSOT 충돌

발견 사항 (≥1건일 때만):

1. [제목]
   - 위치: [정책서/기능설계서 §섹션] vs [SSOT 파일 §섹션]
   - 근거: "[변환 본문 인용]" vs "[SSOT 인용]"
   - 영향: [한 줄]
   - 제안: [최소 수정 또는 확인 조건]
````

자체 품질·SSOT 충돌 모두 0건이면 `## 리뷰 결과: 통과`로만 출력하고 두 sub-section 생략.

입력 제외 0건이면 `## 입력 제외 항목` 섹션 통째로 생략.

### 빈 입력 sanity check

```
입력 비어 있음. 기획 초안 텍스트 또는 경로를 인자로 주세요.
```

literal 빈 문자열·whitespace·0byte 파일·완전 비어 있는 디렉터리에서만 출력. 그 외 모든 케이스는 변환 + 리뷰 흐름으로 진행.

### `--no-review` 사용 시

`## 리뷰 결과` 섹션 전체 생략. 정책서·기능설계서 본문 + (있다면) 입력 제외 항목만 출력.

## 참고 파일

- `templates/기능설계서.md` — 8 섹션 표 골격.
- `templates/정책서.md` — 10 섹션 표 골격.
- `references/review-rules.md` — 자동 리뷰 2축 점검 기준.

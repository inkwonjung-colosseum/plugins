# Exclusion Rules

`planning-format` 입력 제외 추적 룰 — 변환 본문(정책서·기능설계서)에 합류하지 않은 모든 입력 조각을 11 카테고리 중 1개로 라벨링한다. SKILL.md Step 6 변환 직후 1회 Read 적재.

0.2.9부터 기본 화면에는 `## 입력 제외 요약`을 먼저 출력하고, full 5필드 list는 조건 충족 시 하단 `## 상세 추적` 안의 `### 입력 제외 항목`으로 이동한다. 5필드 형식과 11 카테고리는 폐기하지 않는다.

0.2.10부터 `fetch 실패`, `원문 정의 부재`, `라벨 미매핑`, 명시 `[TBD]`는 모두 같은 무게가 아니다. 상태 전이·권한·데이터 변경·외부 인터페이스·재고/금액/수량·필수 입력·기능 동작 판단에 영향을 주는 항목은 결정 보드 후보로 승격하고, 그렇지 않은 항목은 입력 제외 요약/상세 추적에 둔다.

## 1. 11 카테고리

| # | 카테고리 | 정의 |
|---|---|---|
| 1 | `다른 기능 후보` | 기능명 추출 시 1순위 외 후보. 또는 입력에 함께 들어왔지만 별도 기획 대상 |
| 2 | `라벨 미매핑` | 정책서 10 섹션·기능설계서 8 섹션 어디에도 라벨 매핑할 자리가 없음 |
| 3 | `중복` | 같은 사실이 입력에 반복 등장. 한 번만 본문에 합류 |
| 4 | `근거 부족 무시` | 추측·draft 메모·임시 작성으로 본문 신뢰도 떨어뜨림 |
| 5 | `포맷 노이즈` | 인용·꾸밈·자동 metadata·임의 mark-up. 본문 의미 비기여 |
| 6 | `디테일 축약` | 라벨 매핑은 됐으나 본문 디테일 일부가 인접 도메인에 더 가까워 옮기지 않음 |
| 7 | `범위 외` | 정책서 2 / 기능설계서 2 제외 범위에 명시된 영역 |
| 8 | `구조 변환` | 의미는 보존되나 원문 표·구조가 분해돼 다른 섹션 또는 보조 표로 분산. 0.2.8부터 보조 표 상위 섹션/row 추적 정보는 헤더가 아니라 처리 줄에 기록 |
| 9 | `fetch 실패` | 외부 자원(URL·이미지) 본문 미합류. `## 출처` list `본문 사용 = X` 행과 cross-reference. **0.2.5 정의**: fetch **시도 후 실패**만 인정 (인증 게이트·timeout·4xx/5xx·빈 본문·미지원 content-type). fetch 미시도는 `--no-fetch` 1케이스만 가능, 그 외 모든 dequeue URL은 시도 의무. |
| 10 | `원문 정의 부재` | 입력 자체가 모호·미정의. 본문은 [TBD] 처리, 미결 사항 섹션과 cross-reference. **0.2.5**: 3.1 모호성 트리거 정규식·3.2 16 어구 자동 매칭. |
| 11 | `충돌 후보` | 같은 사실(역할·상태·임계·권한)이 입력에서 ≥2 다른 값으로 등장. main이 1순위 값을 본문 합류, 나머지를 본 카테고리로 추적. 본문 셀에 1순위 미명확 시 `[TBD]` + 본 카테고리 cross-ref. |

## 2. 카테고리 우선순위 — 결정 트리 (0.2.5)

한 항목이 둘 이상에 걸치면 결정 트리 위쪽 1개만. 분기 순서 = 현 2 우선순위 그대로 (라벨 미매핑만 폴백으로 이동).

```
입력 조각 X 라벨링:

1. X가 정책서 2 / 기능설계서 2 제외 범위 표 키워드 매칭
   → 범위 외

2. ELIF X가 외부 자원 인용·참조이고 출처 list 본문 사용=X
   → fetch 실패

3. ELIF X가 원문 단일 표·구조이고 본문에서 보조 표로 분해
   → 구조 변환

4. ELIF X가 라벨 매핑은 됐으나 디테일 일부가 인접 도메인
   → 디테일 축약

5. ELIF X가 syntactic 결함 (괄호 미닫힘·"…"·빈 list·공란 row·16 어구)
   → 원문 정의 부재 (자동 [TBD] 본문 합류 + cross-ref)

6. ELIF X가 기능명 추출 후보 list 2위 이하
   → 다른 기능 후보

7. ELIF X가 입력에 ≥2회 등장 + 1회만 본문 합류
   → 중복

8. ELIF X가 추측·draft 메모·임시 작성
   → 근거 부족 무시

9. ELIF X가 cite·markup·metadata·꾸밈
   → 포맷 노이즈

10. ELIF X가 같은 사실에 대한 ≥2 다른 값 단정 인용
    → 충돌 후보

11. ELSE
    → 라벨 미매핑 (폴백 — 8/10 섹션 자리 없음 또는 위 분기 미커버)
```

11 분기 = 11 카테고리 1:1. 라벨 미매핑은 단일 폴백.

### 2.1 트리 진입 조건 (syntactic feature)

각 분기는 syntactic feature 또는 출처 list 행 기준. LLM 의미 해석 최소화:

| 분기 | 진입 조건 |
|---|---|
| `fetch 실패` | 출처 list 행 `본문 사용=X` + 입력 본문에 해당 URL 인용 substring |
| `범위 외` | 정책서/기능설계서 2 제외 표 셀 텍스트 키워드 grep 매칭 |
| `원문 정의 부재` | 정규식 매칭 (`\([^)]*$` 괄호 미닫힘 / `…` 또는 `\.\.\.` / 빈 표 row / 3.2 16 어구) |
| `충돌 후보` | 같은 entity (역할·상태·임계·권한) ≥2 출처에서 다른 값 단정 |
| `구조 변환` | 본문 보조 표(`### N.M`)에 분산 |
| `디테일 축약` | 본문 매핑 row 존재 + 일부 디테일 누락 |
| `중복` | 같은 substring ≥2회 등장 + 1회만 본문 |
| `근거 부족 무시` | "추측" / "draft" / "임시" / "?" 표현 |
| `포맷 노이즈` | XML/HTML 태그·smartlink·metadata 패턴 |
| `다른 기능 후보` | 기능명 추출 후보 list 2위 이하 |

### 2.2 main override

트리 결과가 명백히 부적절하면 main이 override 가능. override 시 입력 제외 섹션 `설명` 줄에 `(main override: <이유>)` 표기 의무.

## 3. 모호성 강제 [TBD] 룰 (0.2.5)

### 3.1 트리거 패턴

다음 syntactic 결함 발견 시 자동 처리. LLM 추론 단정 금지:

| 패턴 | 정규식 / 검출 | 처리 |
|---|---|---|
| 괄호 미닫힘 | `\([^)]*$` (라인 끝) | 본문 셀 `[TBD]` + 카테고리 `원문 정의 부재` |
| 말줄임표 | `…` 또는 `\.\.\.` (확정 표현 끝) | 본문 셀 `[TBD]` |
| 공란 row | 표 셀 모두 빈 string | row 삭제 + 카테고리 `원문 정의 부재` |
| 빈 list | "다음과 같다" / "기본값으로 제공" + 후속 본문 부재 | `[TBD]` |
| 16 어구 (3.2) | substring 매칭 | `[TBD]` + 미결 사항 섹션 항목 |
| "[ ]" / "_____" / "—" 단독 | 셀 본문 | `[TBD]` |

본문 합류 cross-ref:

```
본문 셀: [TBD]
↓
미결 사항 섹션 N: <항목>. 원문 syntactic 결함: <패턴>. 입력 제외 섹션 #M 참조.
↓
입력 제외 섹션 #M: 카테고리 = 원문 정의 부재. 처리 = [TBD] 추적 (미결: 정책서 10 #N).
```

### 3.2 16 어구 카탈로그

| 어구 | 처리 |
|---|---|
| TBD / TODO / FIXME | `[TBD]` |
| 추후 정의 / 추후 결정 / 추후 협의 | `[TBD]` |
| 별도 정의 / 별도 협의 / 별도 확정 | `[TBD]` |
| 확정 시 재정의 / 확정 후 정의 | `[TBD]` |
| 미정 / 미확정 / 미결 | `[TBD]` |
| 기획 시 정의 / 작업 기획 시 구체화 | `[TBD]` |

main이 위 어구 발견 시 단정 추론 금지.

### 3.3 카테고리 경계 처리

- `fetch 실패`는 입력에서 인용·참조된 자원만. 단순 부수 링크는 출처 list에만. fetch 시도 후 실패만 인정 (0.2.5).
- `원문 정의 부재`는 입력 측 결손, `라벨 미매핑`은 변환 측 매핑 결손.
- `충돌 후보`는 입력 측 ≥2 다른 값 단정 인용. 단일 값 + 해석 모호는 `원문 정의 부재`.

## 4. 5필드 형식

하단 상세 추적의 full 항목:

```markdown
1. [한 줄 제목]
   - 카테고리: [1 11종 중 하나]
   - 위치: [출처 N](URL#anchor) [부연 plain text]
   - 인용: "[입력 원문 ≤80자]"
   - 처리: [5 처리 줄 형식]
   - 설명: [한 줄]
```

### 4.1 위치 필드 markdown link 형식 (0.2.4)

위치 필드 첫 부분 = `[출처 N](URL)` markdown link 1개 또는 복수 (콤마 구분). 클릭 = 외부 source 특정 위치 1-hop 점프.

규칙:
- URL = `## 출처` list 행 URL (deep link 형식, `output-contract.md` 출처 list 참조).
- 입력 측 위치(파일명:라인) 추가 정보는 link 뒤 plain text로 (`[출처 3](URL) 줄 42`).
- 출처 미상·로컬 파일은 link 없이 plain text 그대로 (`./docs/draft/주문취소.md:15` / `"직접 입력"`).
- anchor 추출 실패 시 page-level URL fallback (link는 작동, 점프는 page 단위).
- `충돌 후보`는 복수 출처 link 콤마 구분 (`[출처 3](URL#a), [출처 7](URL#b)`).

### 4.2 예시

```markdown
1. 외부 위키 본문 누락
   - 카테고리: fetch 실패
   - 위치: [출처 3](https://confluence.../pages/123#취소-정책) 줄 42
   - 인용: "결제 24시간 내 취소"
   - 처리: 본문 미합류 (출처 list #3 참조)
   - 설명: ...

2. 주문 취소 가능 기간 충돌
   - 카테고리: 충돌 후보
   - 위치: [출처 3](https://confluence.../pages/123#취소-정책), [출처 7](https://docs.../edit#heading=h.xyz)
   - 인용: "24시간" / "7일"
   - 처리: 1순위 값 합류 (정책서 5 / 기능설계서 5), 나머지 추적 (24시간, 7일)
   - 설명: ...
```

## 5. `처리` 줄 형식

| 카테고리 | `처리` 줄 형식 |
|---|---|
| `다른 기능 후보` | `본문 미합류 (별도 기획 대상)` |
| `라벨 미매핑` | `본문 미합류` |
| `중복` | `중복 제거 (1차 합류 위치: 정책서 N / 기능설계서 M)` |
| `근거 부족 무시` | `본문 미합류` |
| `포맷 노이즈` | `본문 미합류` |
| `디테일 축약` | `라벨 매핑은 정책서 N / 기능설계서 M, 디테일 미합류` |
| `범위 외` | `명시 제외 (정책서 2 / 기능설계서 2 참조)` |
| `구조 변환` | `구조 분해 (본문 위치: 정책서 N1·N1.1 / 상위 위치: 정책서 N row M~K; 본문 위치: 기능설계서 M1·M2.1 / 상위 위치: 기능설계서 M row K)` |
| `fetch 실패` | `본문 미합류 (출처 list #K 참조)` |
| `원문 정의 부재` | `[TBD] 추적 (미결: 정책서 10 #N / 기능설계서 8 #M)` |
| `충돌 후보` | `1순위 값 합류 (정책서 N / 기능설계서 M), 나머지 추적 (값 list)` |

매핑·합류 위치를 식별 못 하면 `본문 미합류`로 폴백.

### 5.1 `구조 변환` 위치 표기 (0.2.8)

보조 표 분해가 발생하면 `처리` 줄에 실제 생성된 보조 표 위치와 분해가 발생한 상위 위치를 분리해 기록한다. 보조 표 헤더에는 상위 row backlink를 쓰지 않는다.

필드:

- `본문 위치`: 실제 생성된 보조 표 위치. 예: `정책서 5.1`, `기능설계서 4.1`.
- `상위 위치`: 보조 표 분해가 발생한 상위 섹션 또는 상위 row. 예: `정책서 5 row 7~11`, `기능설계서 4 row 3`.

예:

```markdown
구조 분해 (본문 위치: 정책서 5.1 / 상위 위치: 정책서 5 row 7~11)
구조 분해 (본문 위치: 정책서 5.1 / 상위 위치: 정책서 5 row 7~11; 본문 위치: 기능설계서 4.1 / 상위 위치: 기능설계서 4 row 3)
구조 분해 (본문 위치: 정책서 5.1 / 상위 위치: 정책서 5)
```

상위 row를 식별할 수 없으면 상위 섹션까지만 기록한다.

### 5.2 `충돌 후보` 본문 셀 처리

본문 셀에 1순위 미명확 → `[TBD]` 표기 + 입력 제외 섹션 cross-ref. marker 1종(`[TBD]`) 정책 유지 (`[TBD-CONFLICT]` 등 신설 X).

## 6. 헤더 카운트 분포

0.2.8 이하 헤더 카운트 분포는 0.2.9에서 `## 입력 제외 요약`으로 이동한다. 11 카테고리 카운트는 다음 정보를 보존한다.

```
- 입력 제외: N건 (다른 후보 K, 라벨 미매핑 L, 중복 M, 근거 부족 P, 포맷 노이즈 Q, 디테일 축약 R, 범위 외 S, 구조 변환 T, fetch 실패 U, 원문 정의 부재 V, 충돌 후보 W)
```

규칙:
- 카테고리 카운트가 0인 항목은 괄호에서 누락 (가독성).
- 0건일 때 `- 입력 제외: 없음`.
- 카테고리 라벨은 1 표의 한국어 약형 (`다른 기능 후보` → `다른 후보`, `근거 부족 무시` → `근거 부족`).
- 괄호 안 카운트 합 = N과 일치.
- 기본 요약은 카운트와 영향만 압축한다. full 5필드 항목은 8 조건 충족 시 `## 상세 추적`에 둔다.

## 7. marker 1종 정책

`[TBD]` 1종만. 신설 금지: `[미정]`·`[가정]`·`[확인 필요]`·`[충돌 후보]`·`[TBD-CONFLICT]`·`해당 없음`. 다운스트림 파서 marker 변경 없음.

## 8. 0.2.9 기본 요약과 상세 추적

기본 출력:

```markdown
## 입력 제외 요약

- 총 8건: 범위 외 3, 포맷 노이즈 2, 디테일 축약 2, 구조 변환 1
- 본문 반영에 영향 있는 항목: 없음
- 별도 의사결정 필요: 없음
```

기본 출력에도 상세 1줄을 남겨야 하는 high-signal 항목:

| 조건 | 기본 출력 처리 |
|---|---|
| `fetch 실패` | 실패 source와 본문 영향 1줄 표시 |
| `충돌 후보` | 충돌 값과 선택/미선택 상태 표시 |
| `원문 정의 부재` | 연결된 `[TBD]` 위치 표시 |
| `라벨 미매핑` | 문서 본문 반영 누락 가능성이 있으므로 표시 |

하단 `## 상세 추적`에 full 5필드 list를 반드시 포함하는 조건:

| 조건 | 처리 |
|---|---|
| `충돌 후보`, `원문 정의 부재`, `라벨 미매핑` 1건 이상 | full 5필드 항목 출력 |
| fetch 실패, 인증 실패, 본문 미사용 출처가 1건 이상 | 관련 `fetch 실패` 항목 출력 |
| F5 cross-reference 검증에서 입력 제외 추적 누락 가능성이 발견됨 | 누락된 연결 지점을 출력 |

상세 추적에 넣더라도 `## 정책서`, `## 기능설계서`, `## 검증 피드백`, `## 출처 요약`, `## 입력 제외 요약`보다 먼저 나오면 안 된다.

## 9. 0.2.10 차단 항목 등급화

입력 제외 항목과 본문 `[TBD]`는 다음 등급 중 하나로 분류한다.

| 등급 | 의미 | 상단 노출 |
|---|---|---|
| `출시 전 해결 필요` | 구현·QA·운영 판정을 막는 미정 항목 | `## 결정 보드`의 D*/A*/T* 또는 연결된 D*/A* 차단 사유 |
| `결정 필요` | 출시 전 확정이 바람직하지만 임시 정책이나 non-MVP 제외가 가능 | `지금 결정해야 할 항목` 또는 발견/입력 제외 요약 |
| `후속 과제` | 문서가 명시적으로 후속과제/non-MVP로 제외 | 상단에는 count만, 산출 본문 미결 또는 상세 추적 |
| `추적 로그` | 감사 추적용 fetch 실패, 입력 제외, 라벨 미매핑 | 출처/입력 제외/상세 추적 |

출시 전 해결 필요 판단 기준:

- 상태 전이, 권한, 데이터 변경, 외부 인터페이스, 재고/금액/수량 변경, 사용자 입력 필수값에 직접 영향을 준다.
- 정책서와 기능설계서가 서로 다른 구현 경로를 열어둔다.
- QA가 성공/실패 기준을 쓸 수 없다.
- 운영자가 수행 여부를 판단할 수 없다.

상단 처리:

| 조건 | 처리 |
|---|---|
| 사용자 선택이 필요한 차단 | D* 생성 + `[출시 전 해결]` badge. 반영 작업이 필요하면 A* 생성 |
| 문서 또는 입력 보강만 필요한 차단 | A* 생성 + `[출시 전 해결]` badge. 독립 추적 필요 시에만 T* 생성 |
| 차단 사유가 특정 D*/A*에 이미 연결됨 | 별도 T* 반복 없이 연결 D*/A*에 badge를 붙이고 `출시 전 해결 필요 항목` subsection에 한 줄 사유 |
| 후속 과제/non-MVP로 명시되고 현재 MVP 구현 판정을 막지 않음 | 결정 보드에 펼치지 않음 |
| 핵심 흐름에 영향 없는 fetch 실패 | 출처 요약과 상세 추적에만 유지 |

`--no-self-review`에서도 입력 제외의 `fetch 실패`, `원문 정의 부재`, `라벨 미매핑`, 명시 `[TBD]`가 위 출시 전 해결 필요 기준에 해당하면 결정 보드를 출력한다. 반대로 non-blocking trace만 있으면 결정 보드를 출력하지 않는다.

`라벨 미매핑`은 상태·권한·데이터 변경·외부 인터페이스·재고/금액/수량·사용자 입력 필수값·기능 동작 판단을 막으면 출시 전 해결 필요 항목으로 승격한다. 단순 포맷 노이즈나 기계적 안정화는 승격하지 않는다.

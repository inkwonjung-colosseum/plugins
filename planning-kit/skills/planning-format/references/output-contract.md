# Output Contract

`planning-format` 출력 포맷·헤더 줄 형식·`--save` 처리·출처/입력 제외 요약·하단 상세 추적·`## 출처` list URL deep link·분기별 헤더 형식. SKILL.md Step 8~9 진입 시 1회 Read 적재.

0.2.12 우선 규칙: 최종 응답은 실행 로그가 아니라 산출물이다. `planning-format`은 본문 전에 항상 `## 생성 결과 요약`을 먼저 보여준다. 결정 보드가 필요한 경우에도 순서는 헤더 요약 → 생성 결과 요약 → 결정 보드 → 정책서 → 기능설계서다. 생성 결과 요약은 화면 전용 metadata이며 canonical 본문이나 저장 파일이 아니다.

0.2.11 우선 규칙: 사용자-facing 출력과 저장 파일은 clean display를 사용한다. 섹션 기호를 출력하지 말고 `정책서 5.1`, `기능설계서 7`, `입력 제외 섹션`, `보조 표`처럼 사람이 읽는 위치 표기로 쓴다. 원문 직접 인용 안에 기호가 포함된 경우만 예외다.

0.2.10 호환 규칙: 사용자 확인 필요 항목이나 출시 전 해결 필요 항목이 있으면 `## 결정 보드`를 출력한다. 결정 보드는 사용자가 지금 결정·수정·검증해야 할 항목을 위한 projection이며 canonical 본문이 아니다.

## 1. 출력 블록 순서

```markdown
# [기능명]

- 입력: [사람이 읽는 요약]
- 산출물: 정책서, 기능설계서
- 검증: 피드백 N건, 사용자 확인 필요 M건[, 최우선 확인: 요약 1건] / 피드백 0건, 사용자 확인 필요 없음
- 저장: 없음 (--save 미사용) / planning/[안전기능명]--YYYY-MM-DD-HHMMSS/

---

## 생성 결과 요약

[문서 결과 / 저장 / 검증 상태 / 확인 필요 / 출처 상태 / 입력 제외 상태 / 읽는 순서]

---

## 결정 보드

[사용자 확인 필요 또는 출시 전 해결 필요 항목이 있을 때만 출력]

---

## 정책서

[정책서 본문 - 일반 Markdown]

---

## 기능설계서

[기능설계서 본문 - 일반 Markdown]

---

## 검증 피드백

[피드백 요약 또는 없음]

## 출처 요약

[source type별 요약 + 실패/본문 미사용 행]

## 입력 제외 요약

[카테고리별 카운트 + high-signal 항목]

## 상세 추적

[조건 충족 시에만 full 출처표 / full 입력 제외 5필드 list / fetch status 세부]
```

규칙:

- 최종 출력은 반드시 `# [기능명]`으로 시작한다.
- 최종 출력 앞에 fetch 진행 문장, 도구 fallback 설명, "변환을 시작합니다" 같은 로그 문장을 쓰지 않는다.
- `## 생성 결과 요약`은 항상 헤더 요약 뒤, 첫 `## 정책서` 앞에 둔다.
- 사용자 확인 필요 항목 또는 출시 전 해결 필요 항목이 있으면 `## 결정 보드`가 `## 생성 결과 요약` 뒤와 `## 정책서` 앞에 나온다. 둘 다 없으면 `## 결정 보드`를 생략한다.
- `정책서`와 `기능설계서`는 출처·입력 제외·검증 상세보다 먼저 나온다.
- 기본 화면의 `정책서`와 `기능설계서` 전체를 코드 펜스로 감싸지 않는다.
- 같은 정책서·기능설계서 본문을 읽기용 일반 Markdown과 코드 펜스 원문 블록으로 중복 출력하지 않는다.
- `--no-self-review`면 상단 검증 줄은 `- 검증: 생략 (--no-self-review)`이고 `## 검증 피드백` 섹션은 생략한다.
- self-review를 실행했고 피드백이 0건이면 `## 검증 피드백` 섹션을 유지하고 `없음`을 표시한다.
- self-review를 실행했고 사용자 확인 필요와 출시 전 해결 필요 항목이 모두 없으면 상단 검증 줄에 `사용자 확인 필요 없음`을 명시한다.
- `저장: 화면 only` 표현은 쓰지 않는다. `--save` off는 `- 저장: 없음 (--save 미사용)`으로 쓴다.
- `## 상세 추적`은 조건 충족 시 `## 입력 제외 요약` 뒤에 둔다.
- 반영 위치, 대상, 위치, 처리, 설명 필드에는 clean display를 사용한다. 예: `정책서 5.1 / 기능설계서 7`, `출처 1의 9.1`, `입력 제외 섹션`.

### 1.1 생성 결과 요약

`## 생성 결과 요약`은 화면 전용 metadata 영역이다. 필수 라벨 7개를 각각 정확히 1회 출력한다.

1. `문서 결과`
2. `저장`
3. `검증 상태`
4. `확인 필요`
5. `출처 상태`
6. `입력 제외 상태`
7. `읽는 순서`

규칙:

- non-empty bullet 기준 7줄 이하로 쓴다.
- continuation bullet을 쓰지 않는다.
- `확인 필요`가 없으면 `확인 필요: 없음`으로 쓴다.
- `검증 상태`는 `피드백 없음`, `확인 필요`, `출시 전 해결 필요`, `검증 생략 (--no-self-review)` 중 하나로 시작한다.
- `읽는 순서`는 실제 출력에 존재하는 섹션만 나열한다.
- `## 생성 결과 요약`은 `--save` 저장 파일에 쓰지 않는다.

예:

```markdown
## 생성 결과 요약

- 문서 결과: 정책서와 기능설계서 생성 완료. 화면 본문은 읽기용 표시입니다.
- 저장: 없음 (--save 미사용)
- 검증 상태: 확인 필요 2건, 출시 전 해결 필요 1건
- 확인 필요: 결정 1 (D1) Refurbish 완료 후 재고 속성 / 작업 1 (A1) 귀속 로케이션 컬럼 보강
- 출처 상태: Figma 사용자 흐름 1건 본문 확인 실패, 기능설계서 사용자 흐름 누락 가능
- 입력 제외 상태: 총 21건, 결과 영향 3건은 결정 보드와 연결됨
- 읽는 순서: 생성 결과 요약 → 결정 보드 → 정책서 → 기능설계서 → 검증 피드백 → 상세 추적
```

## 2. 출력 아티팩트 레이어

한 번의 응답 안에서도 다음 레이어를 구분한다.

| 레이어 | 목적 | 출력/저장 위치 | 주요 규칙 |
|---|---|---|---|
| canonical 본문 | 정책서·기능설계서의 의미 기준 | 메모리 내부 + `--save` 파일 | 정책 값·상태·권한·임계값·문구 의미를 보존한다. |
| 생성 결과 요약 | 문서 생성 결과, 저장, 검증 상태, 확인 필요, 출처 영향을 첫 화면에서 압축 | 기본 응답의 헤더 요약 바로 아래 | 필수 7라벨, 7줄 이하. 저장 파일에는 쓰지 않는다. |
| 결정 보드 | 지금 결정·수정·검증할 항목의 action projection | 기본 응답의 `## 생성 결과 요약` 바로 아래 | 자연어 라벨로 D*/A*/T*를 상단 노출. 원시 trace와 connector 세부는 금지. |
| 화면 렌더링 | 채팅 화면에서 바로 읽고 판단하는 표시 | 기본 응답의 `## 정책서`, `## 기능설계서` | 코드 펜스 wrapper 제거, 넓은 표 분해, 긴 셀 bullet화 같은 표시 변환 가능. 의미 변경 금지. |
| 저장 파일 | 원문 Markdown으로 재사용 가능한 산출물 | `planning/[안전기능명]--YYYY-MM-DD-HHMMSS/` | 정책서 1개 + 기능설계서 1개. canonical Markdown 구조를 우선 보존. |
| 검증 피드백 | self-review 발견과 수정 제안 | 기본 응답의 `## 검증 피드백` | 사용자 승인 전 의미 수정 금지. 위치·문제·영향·제안·확인 필요 여부를 표시. |
| 상세 추적 | 출처·입력 제외·fetch status | 하단 `## 상세 추적` | 기본 상단을 방해하지 않도록 하단에 둔다. |

정확한 정책서·기능설계서 원문이 필요하면 `--save` 산출물을 기준으로 삼는다. `--save`를 사용하지 않은 기본 응답은 readable projection이다.

### 2.1 결정 보드

`planning-format`은 다음 중 하나라도 있으면 `## 결정 보드`를 출력한다.

| 조건 | 상단 처리 |
|---|---|
| self-review `사용자 확인 필요: 필요` | D* 생성. 반영 작업이 필요하면 A* 생성 |
| `원문 정의 부재`, `fetch 실패`, `라벨 미매핑`, 명시 `[TBD]`가 상태 전이·권한·데이터 변경·외부 인터페이스·재고/금액/수량·필수 입력·기능 동작 판단을 막음 | 사용자 선택 필요 시 D*, 문서/입력 보강만 필요 시 A*. 출시 전 해결 필요 항목이면 연결 D*/A*에 `[출시 전 해결]` badge와 차단 사유 한 줄 |
| 후속 과제 또는 non-MVP TBD만 있음 | 결정 보드 생략. 산출 본문 미결 또는 입력 제외 요약에 유지 |
| 핵심 흐름에 영향 없는 fetch 실패, 포맷 노이즈, 추적 로그 | 결정 보드 생략. 출처/입력 제외/상세 추적에 유지 |

기본 구조:

```markdown
## 결정 보드

범례: D=결정, A=작업, T=출시 전 해결, F=검증 피드백 원본
읽는 순서: 오늘 결정 → 출시 전 해결 필요 → 바로 수정 → 상세 추적

### 첫 화면 요약

- 오늘 결정: 결정 1 (D1) ...
- 출시 전 해결 필요: 결정 1 (D1) 해소 전 구현·QA 불가
- 바로 수정: 작업 2 (A2) ... / 없음
- 다음 액션: 결정 1 (D1) 확정 후 작업 1 (A1)에 반영

### 지금 결정해야 할 항목

없음

### 출시 전 해결 필요 항목

없음

### 바로 수정할 문서 작업

없음
```

규칙:

- subsection 순서는 `지금 결정해야 할 항목` → `출시 전 해결 필요 항목` → `바로 수정할 문서 작업`이다.
- 항목이 없는 subsection은 heading 아래 본문을 정확히 `없음`으로 표시한다.
- 첫 화면 요약 bullet은 `오늘 결정`, `출시 전 해결 필요`, `바로 수정`, `다음 액션` 중 하나로 시작한다.
- 첫 화면 요약 bullet은 `D1`, `A1`, `T1`, `F5-1`, `P0` 같은 원시 ID로 시작하지 않는다.
- 첫 화면 요약과 카드 제목은 `결정 1 (D1)`, `작업 1 (A1)`, `출시 전 해결 1 (T1)`, `차단 (P0)`처럼 자연어 라벨을 먼저 쓴다.
- `D*` 카드는 `결정 질문`, `선택지`, `초안 추천(확정 필요)`, `결정 필요자`, `반영 위치`, `연결`을 포함한다. 선택지가 부족하면 값을 만들지 말고 `선택지: 확정 필요`로 둔다.
- `A*` 상세 record는 `ID`, `연결`, `유형`, `의존성`, `대상`, `작업`, `완료 조건`, `검증 방법`, `담당/결정 필요자`, `상태`를 보존한다. 상단 카드 제목에는 `[즉시 수정]` 또는 `[D1 대기]` 같은 의존성 badge를 붙일 수 있다.
- `T*` 카드는 `위치`, `차단 이유`, `해소 조건`, `연결`을 포함한다. 특정 D*/A*로 충분히 설명되면 별도 T*를 반복하지 않고 subsection에 차단 사유 한 줄을 남긴다.
- D*/A*/T* ID는 prefix별로 1부터 연속 부여한다. 같은 prefix와 같은 우선순위 안에서는 P0/P1, 출시 전 해결 필요 여부, 입력 등장 순서, 연결 F* 또는 입력 제외 항목 순서로 정렬한다.
- 상단 결정 보드에서는 원시 F* ID를 직접 나열하지 않고 `관련 피드백 N건 (상세 추적의 결정 보드 연결 맵에서 결정 1 (D1)로 확인)`처럼 접는다. 원시 F* mapping은 `## 검증 피드백`, `## 상세 추적`, structured mapping에 유지한다.
- 결정 항목은 최대 3개, 작업 항목은 최대 5개까지만 펼친다. 초과분은 존재하는 섹션만 참조해 `그 외 N건은 검증 피드백/입력 제외 요약/상세 추적 참조`로 압축한다. `발견 요약`은 planning-format 초과 항목 안내에서 참조하지 않는다. 첫 화면 요약의 각 줄은 최대 2개 자연어 라벨과 `외 N건`까지만 표시한다.
- `결정 필요자`를 알 수 없으면 개인명을 만들지 않고 `PM/현업`을 기본값으로 둔다. A* 담당/결정 필요자는 `사용자`, `PM/현업`, `기획`, `운영`, `개발`, `QA` 역할 단위만 쓴다.
- 추천안이 정책 결정을 포함하면 필드명을 `초안 추천(확정 필요)`로 쓰고 사용자 승인 전 canonical 본문에 확정값처럼 반영하지 않는다.
- 상단 결정 보드에는 connector 이름, fetch status code, full source URL table, 원시 source table, 원시 finding 전문을 넣지 않는다.
- 결정 보드는 카드/필드 목록을 기본으로 한다. Markdown 표는 5열 이하이고 모든 표시 문자열 셀이 60자 이하일 때만 쓴다. 60자는 link URL, backtick, 강조 기호를 제거한 표시 문자열 기준이다.

## 3. 헤더 줄 형식

### 3.1 입력 줄

기본 화면은 내부 도구 경로보다 사람이 읽는 요약을 우선한다.

```markdown
- 입력: 직접 입력
- 입력: 파일 2개, 이미지 1개
- 입력: URL 1개, 추가 출처 4개
- 입력: 디렉터리 텍스트 5개, 이미지 2개, 추출 URL 3개
```

도구 경로(`via Atlassian MCP`, `via Google Drive connector`)는 기본 헤더에 쓰지 않는다. 실패나 인증 문제가 있을 때만 `## 출처 요약` 비고에 짧게 남긴다.

### 3.2 검증 줄

| 케이스 | 출력 |
|---|---|
| self-review 실행 + 피드백 0건 | `- 검증: 피드백 0건` |
| self-review 실행 + 피드백 있음 | `- 검증: 피드백 N건, 사용자 확인 필요 M건[, 최우선 확인: <요약>]` |
| `--no-self-review` | `- 검증: 생략 (--no-self-review)` |

사용자 확인 필요 항목이 있으면 최우선 확인 1건을 1줄로만 표시하고, 상세는 `## 검증 피드백`에 둔다.
사용자 확인 필요와 출시 전 해결 필요 항목이 모두 없으면 `사용자 확인 필요 없음`을 같은 줄에 포함한다.

### 3.3 저장 줄

| 케이스 | 출력 |
|---|---|
| `--save` off | `- 저장: 없음 (--save 미사용)` |
| `--save` 성공 | `- 저장: planning/[안전기능명]--YYYY-MM-DD-HHMMSS/` |
| 같은 초 collision | `- 저장: planning/[안전기능명]--YYYY-MM-DD-HHMMSS--2/` |
| `--save` 실패 | `- 저장: 실패 - <사유>. 본문은 화면에 반환.` |

저장 실패는 호출 종료 사유가 아니다. 본문 변환·검증 결과는 화면에 그대로 출력한다.

## 4. 검증 피드백

self-review 발견은 카드/필드 목록 형식으로 출력한다.

```markdown
## 검증 피드백

- 피드백: 2건
- 사용자 확인 필요: 2건

### 피드백 1 (F2-1) 정책서와 화면 동작 표현 혼재

- 위치: 정책서 6
- 구분: cross-bleed
- 문제: `배너 유지`가 정책서 핵심 처리 기준에 있습니다.
- 영향: 정책 기준과 화면 표시 동작이 섞여 구현 기준이 흐려질 수 있습니다.
- 제안: 정책 표현으로 바꾸고 배너 표현은 기능설계서에만 둡니다.
- 사용자 확인: 필요
- 본문 반영 여부: 미반영, 의미 변경 가능
- 결정 보드 연결: 결정 1 (D1)
```

규칙:

- ID는 `F2-1`, `F3-1`, `F4-1`, `F6-1`처럼 self-review 카테고리와 순번을 쓴다. 같은 출력 안에서만 stable하면 된다.
- Markdown 표는 기본 형식이 아니다. 7열 이상의 Markdown 표는 실패다.
- 표는 5열 이하이고 모든 표시 문자열 셀이 60자 이하일 때만 보조적으로 쓸 수 있다.
- 카드 필드는 `위치`, `구분`, `문제`, `영향`, `제안`, `사용자 확인`, `본문 반영 여부`, `결정 보드 연결`을 우선 사용한다.
- 의미 변경이 필요한 F2/F3/F4/F6 발견은 정책서·기능설계서 canonical 본문에 자동 반영하지 않는다.
- 사용자 승인 전에는 `수정 제안 가능`과 `사용자/외부 결정 필요` 항목을 본문에 조용히 반영하지 않는다.
- 기계적 안정화와 화면 전용 표시 변환은 의미 변경 없이 적용 가능하지만, 보정 사실을 검증 피드백 또는 상세 추적에 남긴다.
- 피드백 0건이면 `## 검증 피드백` 아래에 `없음`을 쓴다.

## 5. 출처 요약

기본 출력은 full 출처표를 펼치지 않고 요약한다.

```markdown
## 출처 요약

- 원본 입력: URL 1개
- 추가 출처: 성공 4개 / 실패 0개
- 본문 미사용 출처: 없음

| 종류 | 건수 | 본문 사용 | 비고 |
|---|---:|---:|---|
| Confluence | 2 | 2 | 원본 1, 자식 1 |
| Google Sheets | 2 | 2 | 같은 파일 range 재사용 포함 |
| Figma | 1 | 1 | FigJam board |
```

실패·인증 문제·본문 미사용 출처가 있으면 기본 요약에도 1줄 영향을 남기고, full 표는 `## 상세 추적`에 둔다.

### 5.1 출처 list URL = deep link 형식

하단 `## 상세 추적`의 full `## 출처` 표 행 URL은 anchor 지원 source에서 deep link 형식을 저장한다.

| Source | URL 형식 | 비고 |
|---|---|---|
| WebFetch HTML | `URL#<heading-id>` (있으면) | `<h*> id="..."` parsing. 없으면 page-level. |
| Confluence | `URL#<heading-id>` | `connector-routing.md` 11.1 |
| Google Docs | `URL#heading=h.<digest>` | 11.2 |
| Google Slides | `URL#slide=id.<id>` | 11.3 |
| Notion | `URL#<block-id>` | 11.4 |
| Google Sheets | `URL#gid=<id>&range=<cell>` | 기존 gid/range 처리 |
| Figma | `URL?node-id=<id>` | URL query 그대로 |
| Slack | thread 영구링크 | URL 자체 |
| Jira | page-level (`#comment-<id>` 가능) | summary·description 단위는 anchor 없음 |

추출 실패·미지원 source = page-level URL fallback. 표 행 URL = 입력 제외 섹션 위치 필드 markdown link URL과 동일.

## 6. 입력 제외 요약

기본 출력은 개별 제외 항목을 모두 펼치지 않는다.

```markdown
## 입력 제외 요약

- 총 8건: 범위 외 3, 포맷 노이즈 2, 디테일 축약 2, 구조 변환 1
- 본문 반영에 영향 있는 항목: 없음
- 별도 의사결정 필요: 없음
```

다음 항목은 기본 요약에도 high-signal 1줄을 남긴다.

| 조건 | 기본 출력 처리 |
|---|---|
| `fetch 실패` | 실패 source와 영향 1줄 표시 |
| `충돌 후보` | 충돌 값과 선택/미선택 상태 표시 |
| `원문 정의 부재` | 연결된 `[TBD]` 위치 표시 |
| `라벨 미매핑` | 문서 본문 반영 누락 가능성이 있으므로 표시 |

full 5필드 항목 list는 7 조건 충족 시 하단 `## 상세 추적`에 둔다. 5필드 형식은 `exclusion-rules.md` 4를 유지한다.

## 7. 상세 추적

새 옵션을 추가하지 않는다. 기존 출력에 포함되던 상세 추적 정보는 조건 충족 시 하단으로 이동한다.

`## 상세 추적` 출력 조건:

| 조건 | 처리 |
|---|---|
| fetch 실패, 인증 실패, 본문 미사용 출처가 1건 이상 | full `## 출처` 표를 반드시 포함 |
| `충돌 후보`, `원문 정의 부재`, `라벨 미매핑`이 1건 이상 | full `## 입력 제외 항목` 5필드 항목을 반드시 포함 |
| D*/A*/T*가 원시 F* 또는 입력 제외 항목을 접어 표시함 | `### 결정 보드 연결 맵` 포함 |
| 기계적 안정화 또는 화면 전용 표시 변환이 발생 | 보정 사실과 위치를 포함 |
| 모두 성공이고 제외/발견이 요약으로 충분 | 상세 추적 생략 가능 |

상세 추적을 출력하더라도 기본 상단보다 먼저 나오면 안 된다.

### 7.1 Full 출처 표

```markdown
### 출처

원본 입력: <직접 입력 / 파일 N개 / 디렉터리 텍스트 N개 / URL M개 / 이미지 I개>
재귀 fetch: 성공 N개 / 실패 K개 (cap 없음)

| # | depth | 출처 종류 | URL/경로 또는 위치 | 상태 | 본문 사용 |
|---|---:|---|---|---|---|
| 0 | - | 원본 | 직접 입력 / 파일 / 디렉터리 / - | - | O (원본) |
| 1 | 0 | 인자 URL | <Confluence URL>#취소-정책 | 200 (via Atlassian MCP) | O |
| 2 | 1 | 자식 URL | <Sheets URL>#gid=0&range=C13 (출처: [#1] line N) | 200 (via Google Drive connector - read_file_content) | O |
```

### 7.2 Full 입력 제외 항목

```markdown
### 입력 제외 항목

1. [한 줄 제목]
   - 카테고리: [11종 중 하나]
   - 위치: [출처 N](URL#anchor) [부연 plain text]
   - 인용: "[입력 원문 <=80자]"
   - 처리: [exclusion-rules.md 5 처리 줄]
   - 설명: [왜 본문에 안 넣었는지 한 줄]
```

### 7.3 결정 보드 연결 맵

```markdown
### 결정 보드 연결 맵

- D1 -> F5-1
- A1 -> D1, F5-1
```

상단 결정 보드에서는 원시 F* ID를 접어 표시하고, 이 mapping과 `## 검증 피드백`에서 원본을 확인할 수 있게 한다.

## 8. `--save` 처리

### 8.1 저장 경로

`--save`는 현재 작업 디렉터리 기준 `planning/` 아래에만 저장한다.

```text
planning/[안전기능명]--YYYY-MM-DD-HHMMSS/
  [안전기능명]_정책서.md
  [안전기능명]_기능설계서.md
```

규칙:

- 숨김 폴더인 `.planning-kit/`은 신규 저장 경로로 사용하지 않는다.
- 저장 파일 개수는 정책서 1개 + 기능설계서 1개다.
- 저장 파일에는 `## 생성 결과 요약`, 자체 검증 피드백, 출처 요약, 입력 제외 요약, 상세 추적을 쓰지 않는다.
- 저장 파일에는 top-level `## 결정 보드`를 쓰지 않는다.
- 저장 파일은 화면용 카드/필드 목록이 아니라 canonical Markdown 구조를 우선 보존한다.
- 저장 폴더는 review 대상 입력이 될 수 있다.
- 저장 폴더와 그 하위 파일은 기준 문서 묶음 근거가 될 수 없다.
- `planning/` 폴더는 생성 산출물·작업 초안·review target의 영역이며 기준 문서 저장소가 아니다.

### 8.2 기능명 안전화

1. NFC normalize.
2. 경로 분리자(`/`, `\`), 컨트롤 문자, 파일명 금지 문자(`:`, `*`, `?`, `"`, `<`, `>`, `|`)를 `-`로 바꾼다.
3. 양끝 공백·마침표를 제거한다.
4. 결과가 비면 `untitled`를 사용한다.
5. 80자를 넘으면 Unicode grapheme cluster 경계에서 80자 이하로 자르고, 자른 뒤 양끝 공백·마침표를 다시 제거한다.
6. Windows 예약 basename(`CON`, `PRN`, `AUX`, `NUL`, `COM1`~`COM9`, `LPT1`~`LPT9`)은 대소문자 무관으로 금지하고 뒤에 `-file`을 붙인다.

### 8.3 Timestamp와 collision

- timestamp는 사용자 locale 기준 현재 시각을 `YYYY-MM-DD-HHMMSS`로 기록한다.
- 같은 초에 폴더명이 충돌하면 폴더명 끝에 `--2`, `--3` suffix를 붙인다.
- 기존 파일을 덮어쓰지 않는다.

## 9. Readable Projection Parser

`planning-review`와 downstream parser는 기본 화면 출력을 readable projection으로만 취급한다.

1. 저장 경로가 있으면 화면 projection보다 `--save` 파일을 우선한다.
2. wrapper heading은 줄 시작의 정확한 H2만 인정한다. CRLF는 LF로 정규화하고, 파일 첫 BOM은 무시하며, trailing whitespace는 제거한다. leading space, closing hash(`## 결정 보드 ##`), H3 이하 heading은 wrapper로 인정하지 않는다.
3. fenced code block 안, blockquote 안, 리스트 하위의 `## 결정 보드` 문자열은 wrapper heading으로 보지 않는다. fenced code block은 backtick fence와 tilde fence를 모두 포함한다.
4. 닫히지 않은 fenced code block이 있으면 이후 heading은 wrapper로 인정하지 않고 `readable projection boundary ambiguous` warning을 남긴다.
5. 정상 위치의 `## 생성 결과 요약`은 헤더 요약 뒤, 첫 `## 정책서` 앞이다. `## 결정 보드`가 있으면 `## 생성 결과 요약` 뒤에 온다.
6. 정상 위치의 `## 생성 결과 요약`은 report metadata로 취급하고 정책서·기능설계서 본문에 포함하지 않는다.
7. 같은 metadata 영역에 두 번째 `## 생성 결과 요약`이 있으면 duplicate로 처리하고 warning 문자열은 `readable projection boundary ambiguous`로 남긴다.
8. `## 생성 결과 요약` 내부의 code fence, blockquote, list child heading, heading-like text는 정책서·기능설계서 본문 추출에 포함하지 않는다.
9. 첫 `## 정책서`보다 앞의 첫 번째 `## 결정 보드`만 report metadata로 취급한다.
10. 같은 metadata 영역에 추가 `## 결정 보드`가 있으면 duplicate decision board로 보고 해당 line부터 다음 인정된 wrapper H2 직전까지 body에서 제외하며 `readable projection boundary ambiguous` warning을 남긴다.
11. 정책서 본문은 첫 `## 정책서` wrapper heading 다음 줄에서 시작해 다음 wrapper heading 중 먼저 등장하는 `## 기능설계서`, `## 검증 피드백`, `## 출처 요약`, `## 입력 제외 요약`, `## 상세 추적`, `## 결론`, `## 최우선 수정 항목`, `## 작업 백로그`, EOF까지다.
12. 기능설계서 본문은 첫 `## 기능설계서` wrapper heading 다음 줄에서 시작해 다음 wrapper heading 중 먼저 등장하는 `## 검증 피드백`, `## 출처 요약`, `## 입력 제외 요약`, `## 상세 추적`, `## 결론`, `## 최우선 수정 항목`, `## 작업 백로그`, EOF까지다.
13. `## 결정 보드`와 `## 생성 결과 요약`은 정책서·기능설계서 본문 경계로 사용하지 않는다. metadata 위치가 아닌 곳에 나타나면 invalid wrapper sentinel로 감지하고, 해당 line부터 다음 인정된 wrapper H2 직전까지 body에서 제외하며 `readable projection boundary ambiguous` warning을 남긴다.
14. 생성된 정책서·기능설계서 본문 안에서는 `## 생성 결과 요약`, `## 결정 보드`, `## 검증 피드백`, `## 출처 요약`, `## 입력 제외 요약`, `## 상세 추적`을 최상위 wrapper heading으로 쓰지 않는다. 본문에서 같은 의미의 heading이 필요하면 `###` 이하 하위 heading을 사용한다.
15. 0.2.11 이하 산출물처럼 `## 생성 결과 요약`이 없는 입력은 legacy readable projection으로 계속 읽는다.
16. 경계가 둘 이상으로 해석되거나 한쪽 본문을 확정할 수 없으면 임의 병합하지 않는다.

## 10. 사용자-facing 용어

기본 상단 출력은 내부 도구 용어보다 한국어 업무 용어를 우선한다.

| 내부/기술 용어 | 기본 화면 권장 표기 |
|---|---|
| `Action Backlog` / `액션 Backlog` | `작업 백로그` |
| `D1` | `결정 1 (D1)` |
| `A1` | `작업 1 (A1)` |
| `T1` | `출시 전 해결 1 (T1)` |
| `P0` | `차단 (P0)` |
| `P1` | `중요 (P1)` |
| `P2` | `권고 (P2)` |
| `placeholder` | `본문 없는 문서` |
| `SSOT corpus` | `기준 문서 묶음` |
| `SSOT token 폴더` | ``SSOT` 표시가 있는 기준 문서 폴더` |
| `raw markdown` | `붙여 넣은 Markdown 원문` |
| `fetch` | `본문 가져오기` 또는 `외부 본문 확인` |
| `deps` | `영향 분석` |
| `AC Blocker` | `구현/QA 차단` |
| `connector fallback` | 기본 상단 노출 금지. 실패/인증 문제가 있을 때만 출처 요약 비고에 짧게 표시 |

상세 추적 섹션에서는 기존 parser 호환을 위해 `SSOT corpus`, `fetch`, `connector` 같은 기존 기술 용어를 병기할 수 있다.

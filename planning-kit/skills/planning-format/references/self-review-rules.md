# Self-Review Rules

`planning-format` 자체 품질 검증의 6 카테고리 기준. **0.2.5부터 6패스 체크리스트** — 카테고리당 1패스, 총 27 항목 yes/no 검사(0.2.8 F6 legacy backlink 헤더 금지 포함). 체크리스트 □ 중 unchecked 1개 = 발견 1건.

## 용어

- **변환 본문**: 같은 턴에서 main이 작성한 정책서·기능설계서 markdown.
- **입력**: 사용자가 넘긴 텍스트·파일·디렉터리·URL·이미지 원문 + 재귀 fetch 본문 + multimodal 해석 통합.
- **확정 문장**: 변환 본문 중 `[TBD]`가 아닌 단정 표현.

## F1. 섹션 충실도

- `[TBD]` 비율 50% 초과 → 발견. **sub-§(`### N.M ... 보조 표`) 본문도 포함해서 카운트** (0.2.4).
- 빈 row (표 헤더만 있고 데이터 row 0) → 발견. **보조 표 헤더만 있고 row 0이면 빈 row 발견** (0.2.4).
- 빈 섹션 (헤더만 남고 본문·표 모두 비어 있음) → 발견. **빈 sub-§도 동일 기준** (0.2.4).

### F1 체크리스트 (5 항목, 0.2.5)

```
□ 정책서 §1~§10 각각 본문 row ≥1 있나
□ 기능설계서 §1~§8 각각 본문 row ≥1 있나
□ 보조 표 §N.M 각각 데이터 row ≥1 있나
□ 정책서 [TBD] / 본문 셀 비율 ≤50%
□ 기능설계서 [TBD] / 본문 셀 비율 ≤50%
```

## F2. 라벨 cross-bleed

- 정책서에 `화면`/`버튼`/`입력 폼`/`클릭`/`이동` 등 화면·동작 단어가 핵심 규칙 자리 차지 → 발견.
- 기능설계서에 `허용`/`금지`/`예외 승인`/`판단 기준` 같은 정책 단어가 동작 row 자리 차지 → 발견.
- 경계: 정책서가 화면 이름 단순 참조(`주문 화면에서`)는 cross-bleed 아님.
- **sub-§(`### N.M ... 보조 표`) 본문도 점검 대상** — 정책서 sub-§ 안 화면·동작 단어, 기능설계서 sub-§ 안 정책 단어는 부모 § 룰 그대로 sub-§ 확장 (0.2.4).

### F2 체크리스트 (4 항목, 0.2.5)

```
□ 정책서 §3~§10 본문에 "화면"/"버튼"/"입력 폼"/"클릭" 단어 부재
□ 기능설계서 §4~§7 본문에 "허용"/"금지"/"예외 승인" 단어 부재
□ 정책서 sub-§ 본문에 화면 동작 단어 부재
□ 기능설계서 sub-§ 본문에 정책 단어 부재
```

## F3. 두 문서 간 용어 일관성

- 같은 대상의 표기가 다르면 발견. 비교 대상:
  - 역할명 (`관리자` vs `Admin` vs `운영자`)
  - 상태명 (`취소` vs `cancelled` vs `취소됨`)
  - 권한명 (`읽기` vs `read` vs `조회`)
  - 도메인 stem (`주문` vs `order` vs `주문서`)
- 한 문서 안에서 흔들려도 발견.
- `[TBD]`만 들어간 셀은 비교 대상 아님.

### F3 체크리스트 (4 항목, 0.2.5)

```
□ 역할명 표기 통일 (1 표기/entity)
□ 상태명 표기 통일
□ 권한명 표기 통일
□ 도메인 stem 통일
```

## F4. 정책-기능 매핑

- 정책서 §5(세부 규칙)·§6(상태 처리) 규칙이 기능설계서 §5(기능 동작)·§7(예외)에 누락 → 발견.
- 정책서 `금지` 액션이 기능설계서에서 정상 흐름으로 표기 → 발견.
- 정책서 §7 역할 권한이 기능설계서 §6 권한·데이터 접근과 어긋남 → 발견.

### F4 체크리스트 (4 항목, 0.2.5)

```
□ 정책서 §5 규칙 1개당 기능설계서 §5 또는 §7 매핑 ≥1
□ 정책서 §6 상태 전이 1개당 기능설계서 §5 액션 매핑 ≥1
□ 정책서 §7 권한 1개당 기능설계서 §6 행 매핑 ≥1
□ 정책서 `금지` 액션이 기능설계서 정상 흐름 부재
```

## F5. 누락 핵심 정보

### F5.1 본문 누락 (기존 점검)

- 입력의 명시 사실(역할·상태·기능명·수치 임계)이 두 본문·입력 제외 추적에 모두 부재 → 발견.
- 입력의 대화 메모·진행 톤은 누락 대상 아님.

### F5.2 cross-reference 점검 (신규)

입력 제외 §은 본문에 합류하지 않은 모든 입력 조각의 단일 추적 위치다. 다음 3 cross-reference가 어긋나면 발견.

#### F5.2.1 sub: `cross-ref-fetch`

- `## 출처` list에 `본문 사용 = X` 행이 ≥1건이고, 해당 자원이 입력에서 단순 부수 링크가 아닌 경우(인용·참조 문장에 언급).
- 입력 제외 §에 같은 자원에 대한 `fetch 실패` 카테고리 항목이 없으면 발견.

#### F5.2.2 sub: `cross-ref-scope`

- 정책서 §2 / 기능설계서 §2 제외 범위 표 cell에서 키워드 추출 + 입력 본문에서 grep 매칭.
- 매칭 키워드가 입력 본문에 있는데 입력 제외 §에 `범위 외` 카테고리 항목이 없으면 발견.

#### F5.2.3 sub: `cross-ref-tbd`

- 정책서 §10 / 기능설계서 §8 미결 항목 중 다음 표현이 들어간 항목을 추출:
  - `원문 명시 없음` / `원문 정의 부재` / `입력 미정` / `원본 본문에 없음`
- 위 표현이 미결 §에 있는데 입력 제외 §에 `원문 정의 부재` 카테고리 항목이 없으면 발견.

### F5.3 발견 사항 형식

cross-reference 발견은 카테고리 표기에 sub-label 표시:

```markdown
1. fetch 실패 항목이 입력 제외 §에 추적 안 됨
   - 카테고리: 누락 (sub: cross-ref-fetch)
   - 위치: 출처 list #3 (Figma board) ↔ 입력 제외 § (해당 카테고리 항목 부재)
   - 근거: "출처 list 행에 인증 실패. 입력 §2 사용자 흐름에서 다이어그램으로 인용됨"
   - 영향: 사용자가 다이어그램 누락을 입력 제외 §에서 확인 못 함
   - 제안: 입력 제외 §에 `fetch 실패` 카테고리 항목 추가 (출처 list #3 cross-reference)
```

### F5 체크리스트 (4 항목, 0.2.5)

```
□ F5.1 본문 누락: 입력 명시 사실(역할·상태·기능명·수치 임계) 모두 본문/입력 제외 § 등장
□ F5.2.1 cross-ref-fetch: 출처 list `본문 사용=X` 행마다 입력 제외 § `fetch 실패` 항목 매칭
□ F5.2.2 cross-ref-scope: 정책서/기능설계서 §2 제외 표 키워드 → 입력 제외 § `범위 외` 항목 매칭
□ F5.2.3 cross-ref-tbd: 미결 § "원문 명시 없음" 등 어구 → 입력 제외 § `원문 정의 부재` 항목 매칭
```

## F6. Markdown syntax lint

코드 펜스 안 본문이 깨지면 출력 markdown이 무너진다. 다음만 점검:

- **펜스 짝**: ` ``` `의 짝 (열고 안 닫음 / 닫음 부족 / inline에 잘못 등장).
- **표 컬럼 수**: 헤더 `|---|---|` 컬럼 수와 row `|` 카운트 불일치.
- **헤더 레벨 점프**: `#` 다음 첫 자식 헤더가 `###` 이상 (`[TBD]` 셀로 인한 점프는 예외). **`## §N → ### N.M [용도] 보조 표` 정상 case는 점프 아님** — 0.2.3 sub-§ 도입 후속.
- **보조 표 legacy backlink 헤더**: 0.2.8 이후 신규 출력에서 `### N.M ... 보조 표 (§N row M)` 또는 `### N.M ... 보조 표 (§N)` 패턴이 남으면 syntax 발견. legacy 문서를 `planning-review`가 읽는 경우에는 강제 발견하지 않는다.
- **빈 인용 부호**: `> ` 한 줄만 + 다음 줄 비어 있음.
- **list marker 일관성**: 같은 list 안 `-`와 `*` 혼용 / `1.`·`2.` 순서 깨짐.

위치는 line 번호로 명시. 카테고리 라벨 = `syntax`.

### F6 체크리스트 (6 항목, 0.2.8)

```
□ 코드 펜스 짝 맞음
□ 표 컬럼 수 일치
□ 헤더 레벨 점프 없음 (sub-§ 정상 case 제외)
□ 신규 보조 표 헤더에 `(§...)` legacy backlink 없음
□ 빈 인용 부호 없음
□ list marker 일관
```

## 6패스 진행 (0.2.5)

체크리스트 27 항목 (F1: 5 + F2: 4 + F3: 4 + F4: 4 + F5: 4 + F6: 6) 을 6 카테고리 단위로 묶어 6패스 진행 (카테고리당 1패스). 단일 LLM 패스로 "발견 있나요?"만 묻지 말고 항목별 yes/no 답.

체크리스트 □ 중 unchecked 1개 = 발견 1건. 발견 0건 = 통과. 발견 ≥1건 = `발견 N건`. 발견 분포 헤더(`충실도 N건·cross-bleed N건·...`) 그대로.

추가 비용: 2~5초 (체크리스트 형식 짧음).

# Self-Review Rules

`planning-format` 자체 품질 검증의 6 카테고리 기준.

## 용어

- **변환 본문**: 같은 턴에서 main이 작성한 정책서·기능설계서 markdown.
- **입력**: 사용자가 넘긴 텍스트·파일·디렉터리·URL·이미지 원문 + 재귀 fetch 본문 + multimodal 해석 통합.
- **확정 문장**: 변환 본문 중 `[TBD]`가 아닌 단정 표현.

## F1. 섹션 충실도

- `[TBD]` 비율 50% 초과 → 발견.
- 빈 row (표 헤더만 있고 데이터 row 0) → 발견.
- 빈 섹션 (헤더만 남고 본문·표 모두 비어 있음) → 발견.

## F2. 라벨 cross-bleed

- 정책서에 `화면`/`버튼`/`입력 폼`/`클릭`/`이동` 등 화면·동작 단어가 핵심 규칙 자리 차지 → 발견.
- 기능설계서에 `허용`/`금지`/`예외 승인`/`판단 기준` 같은 정책 단어가 동작 row 자리 차지 → 발견.
- 경계: 정책서가 화면 이름 단순 참조(`주문 화면에서`)는 cross-bleed 아님.

## F3. 두 문서 간 용어 일관성

- 같은 대상의 표기가 다르면 발견. 비교 대상:
  - 역할명 (`관리자` vs `Admin` vs `운영자`)
  - 상태명 (`취소` vs `cancelled` vs `취소됨`)
  - 권한명 (`읽기` vs `read` vs `조회`)
  - 도메인 stem (`주문` vs `order` vs `주문서`)
- 한 문서 안에서 흔들려도 발견.
- `[TBD]`만 들어간 셀은 비교 대상 아님.

## F4. 정책-기능 매핑

- 정책서 §5(세부 규칙)·§6(상태 처리) 규칙이 기능설계서 §5(기능 동작)·§7(예외)에 누락 → 발견.
- 정책서 `금지` 액션이 기능설계서에서 정상 흐름으로 표기 → 발견.
- 정책서 §7 역할 권한이 기능설계서 §6 권한·데이터 접근과 어긋남 → 발견.

## F5. 누락 핵심 정보

- 입력의 명시 사실(역할·상태·기능명·수치 임계)이 두 본문·입력 제외 추적에 모두 부재 → 발견.
- 입력의 대화 메모·진행 톤은 누락 대상 아님.

## F6. Markdown syntax lint

코드 펜스 안 본문이 깨지면 출력 markdown이 무너진다. 다음만 점검:

- **펜스 짝**: ` ``` `의 짝 (열고 안 닫음 / 닫음 부족 / inline에 잘못 등장).
- **표 컬럼 수**: 헤더 `|---|---|` 컬럼 수와 row `|` 카운트 불일치.
- **헤더 레벨 점프**: `#` 다음 첫 자식 헤더가 `###` 이상 (`[TBD]` 셀로 인한 점프는 예외).
- **빈 인용 부호**: `> ` 한 줄만 + 다음 줄 비어 있음.
- **list marker 일관성**: 같은 list 안 `-`와 `*` 혼용 / `1.`·`2.` 순서 깨짐.

위치는 line 번호로 명시. 카테고리 라벨 = `syntax`.

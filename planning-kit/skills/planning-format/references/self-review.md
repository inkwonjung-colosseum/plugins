# Self-Review

`--no-self-review`가 아니면 생성 후 실행한다. 자가검증은 피드백 게이트지 자동 재작성 패스가 아니다. 기계적 수정은 적용할 수 있고, 의미 변경은 사용자 승인 대상이라 `## 체크해야 할 항목`으로 보낸다.

## 검증 제외 (먼저 적용)

- 타이틀 "미결 사항"(정책서 10절, 기능설계서 10절) 섹션은 검증하지 않는다.
- 정책서 내 `(Non-MVP)` 표기 항목은 검증하지 않는다.
- 제외 대상은 아래 모든 패스(완전성·레이어·링크·출처)에서 빠진다.

## 패스

R1 섹션 완전성:

- 정책서 1-11, 기능설계서 1-7·10-11 각 섹션이 내용 또는 명시적 `[TBD]` + 체크리스트 미러를 가진다.
- 기능설계서 번호 8·9는 결번이므로 비어 있어야 정상이다 (finding 아님).
- `[TBD]` 비율이 지배적이지 않다.

R2 레이어 분리 (경량):

- 정책서 핵심 규칙이 버튼·클릭·입력폼 같은 UI 단어로 쓰이지 않는다.
- 기능설계서가 허용/금지/승인 규칙의 출처 노릇을 하지 않는다.
- 구현 상세(데이터 모델·API 계약·NFR 수치·테스트)와 PM 전략 장식(RACI·RICE/MoSCoW·리스크 레지스터·로드맵 게이트·페르소나·여정 감정곡선)이 어느 문서에도 없다. 등장하면 finding.

R3 POL↔FUNC 링크:

- 기능 흐름·동작은 관련 정책(`POL-XXX`)을 참조하거나, 정책과 무관한 운영 동작임을 한 줄로 밝힌다.
- 정책 규칙은 관련 기능 동작(`FUNC-XXX`)을 선택적으로 참조할 수 있다 (필수 아님).
- `POL-`·`FUNC-` 외 prefix가 등장하면 finding.

R4 출처 누락:

- 명시된 역할·상태·기능명·임계값·권한 사실이 문서나 제외 목록에 있다.
- fetch 실패·범위 제외·정의 누락이 교차 참조된다.

R5 Markdown 정합:

- fence 쌍과 헤더 레벨이 정상이다.
- 생성 본문에 예약 래퍼 헤딩이 없다.

## 분류

- 기계적 안정화: 본문 수정 가능.
- 표시 전용 변환: 렌더링만 수정.
- 제안 수정 / 사용자·외부 결정: 체크리스트 우선, 본문 유지.

findings가 없으면 `## 체크해야 할 항목`에 `없음`이라고 쓴다.

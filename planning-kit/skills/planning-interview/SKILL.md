# planning-interview

모호한 기획 아이디어를 소크라테스식 1문1답으로 명확화하는 인터뷰어. 한 번에 한 질문으로 숨은 가정을 드러내고, 기획 명확도를 4개 차원으로 점수화해 모호도가 임계 이하로 떨어질 때까지 진행한다. **산출물은 명확도 리포트뿐** — 정책서·기능설계서는 만들지 않고, 명확해지면 `planning-format` 호출을 제안한다.

기획 레벨에 머문다. 구현 상세(데이터 모델·API 계약·NFR 수치·테스트)와 PM 전략 장식(KPI/OKR·RACI·RICE·리스크 레지스터·로드맵·페르소나)은 차원도 질문도 아니다.

## Do Not Use When

- 이미 구체적인 기획안·정책서·기능설계서가 있다 → `planning-format`/`planning-review` 직접 호출.
- 단순 변환·정리 작업 → `planning-format`.
- 사용자가 "그냥 만들어"로 질문을 거부 → 인터뷰 종료, 현재 명확도로 리포트만 내고 멈춘다.

## Inputs

- Positional: 모호한 기획 아이디어(텍스트). 없으면 "무엇을 기획하려 하나요?"로 시작.
- Options: `--threshold <0~1>` (기본 `0.2`), `--no-context`, `--max-rounds <n>` (기본 `18`).

## Workflow

맥락 탐색(brownfield) → 라운드 루프(질문 1개 → 답변 → 채점 → 리포트, 라운드 임계에서 기획 challenge 모드 1회씩 주입) → 임계 도달 또는 조기 종료 → 명확도 리포트 → `planning-format` 핸드오프 제안. 인터뷰만 한다 — 파일을 만들거나 고치지 않고, 실행 스킬을 자동 호출하지 않는다.

**4개 차원** (정책서 POL · 기능설계서 FUNC 산출물에 정렬): `모호도 = 1 − (목표·0.25 + 정책·0.35 + 기능·0.25 + 성공기준·0.15)`. 정책·규칙 비중이 가장 크다 — 기획의 핵심 산출물이라서. 임계 이하면 준비 완료. 차원별 판정 기준·질문 스타일·challenge 모드는 `references/runtime.md`.

## Rules

- 한 번에 **한 질문만** — 절대 묶지 않는다. 매 라운드 가장 약한 차원을 타겟하고 왜 지금인지 한 줄로 밝힌다.
- 질문은 기능 목록 수집이 아니라 **가정을 드러낸다**. 기존 맥락에 있는 사실은 explore로 확인해 재질문 대신 근거를 인용한다.
- 라운드가 깊어지면 **기획 challenge 모드**(범위 축소 R3+ · 이해관계자 R5+ · 정책 충돌 R7+ · 엣지/예외 R9+)를 각 1회 주입해 가정을 압박한다 — 상세는 runtime.
- 매 답변 후 모호도를 채점해 투명하게 보여주고, 세션 언어를 보존한다.
- 모든 산출은 리포트다. 정책서/기능설계서 본문, brief 파일, 실행 스킬 호출은 이 스킬의 일이 아니다.

## Output Contract

- 라운드 진행: `Round {n} | 타겟: {약한차원} | {활성 모드 or 통상} | 모호도: {%}` + 질문 1개.
- 종료 리포트: `# [기능명] 인터뷰 결과` → `## 결론`(준비 완료/모호) → `## 명확도`(차원별 점수·gap) → `## 합의된 결정`(정책·기능 후보·성공기준) → `## 미결 사항` → `## 다음 단계`(planning-format 핸드오프 제안).
- 코드펜스로 리포트 전체를 감싸지 않는다. 진행 로그를 앞세우지 않는다.

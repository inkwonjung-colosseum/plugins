# planning-interview

모호한 기획 아이디어를 소크라테스식 1문1답으로 명확화하는 인터뷰어. 한 번에 한 질문으로 숨은 가정을 드러내고, 기획 명확도를 4개 차원으로 점수화해 모호도가 임계 이하로 떨어질 때까지 진행한다. **산출물은 명확도 리포트뿐** — 정책서·기능설계서는 만들지 않고, 리포트가 명확해지면 `planning-format` 호출을 제안한다.

기획 레벨에 머문다. 구현 상세(데이터 모델·API 계약·NFR 수치·테스트)와 PM 전략 장식(KPI/OKR·RACI·RICE·리스크 레지스터·로드맵·페르소나)은 차원도 질문도 아니다.

## Do Not Use When

- 이미 구체적인 기획안·정책서·기능설계서가 있다 → `planning-format`/`planning-review` 직접 호출.
- 단순 변환·정리 작업 → `planning-format`.
- 사용자가 "그냥 만들어"라며 질문을 거부 → 인터뷰 종료, 현재 명확도로 리포트만 내고 멈춘다.

## Inputs

- Positional: 모호한 기획 아이디어(텍스트). 없으면 "무엇을 기획하려 하나요?"로 시작.
- Options: `--threshold <0~1>` (기본 `0.2`), `--no-context` (기존 기획 맥락 탐색 생략), `--max-rounds <n>` (기본 `12`).

## Workflow

맥락 탐색(brownfield) → 라운드 루프(질문 1개 → 답변 → 채점 → 리포트) → 임계 도달 또는 조기 종료 → 명확도 리포트 → `planning-format` 핸드오프 제안. 인터뷰만 한다 — 파일을 만들거나 고치지 않고, 실행 스킬을 자동 호출하지 않는다.

**4개 차원** (정책서 POL · 기능설계서 FUNC 산출물에 정렬):

| 차원 | 가중치 | 무엇이 명확한가 |
|---|---|---|
| 목표 | 0.35 | 이 기획이 달성하려는 것을 한 문장으로 말할 수 있나 |
| 정책·규칙 | 0.25 | 허용/금지/승인·상태·역할·예외 경계가 분명한가 (POL- 후보) |
| 기능·흐름 | 0.25 | 사용자가 무엇을 하고 시스템이 무엇을 하나 (FUNC- 후보) |
| 성공기준 | 0.15 | 됐는지 검증 가능한가 |

`모호도 = 1 − (목표·0.35 + 정책·0.25 + 기능·0.25 + 성공기준·0.15)`. 임계 이하면 준비 완료.

## Rules

- 한 번에 **한 질문만** — 절대 묶지 않는다. 매 라운드 가장 약한 차원을 타겟하고, 왜 지금 그 차원인지 한 줄로 밝힌다.
- 질문은 기능 목록 수집이 아니라 **가정을 드러낸다**.
- 기존 기획 맥락(planning 폴더·SSOT 표시 문서·관련 정책서)에 이미 있는 사실은 explore로 먼저 확인하고, 재질문 대신 근거를 인용해 확인만 받는다.
- 매 답변 후 모호도를 채점해 투명하게 보여준다.
- 세션 언어를 보존한다 — 한글 입력에는 한글 질문.
- 모든 산출은 리포트다. 정책서/기능설계서 본문, brief 파일, 실행 스킬 호출은 이 스킬의 일이 아니다.

## Output Contract

- 라운드 진행: `Round {n} | 타겟: {약한차원} | 모호도: {%}` + 질문 1개.
- 종료 리포트: `# [기능명] 인터뷰 결과` → `## 결론`(준비 완료/모호) → `## 명확도`(차원별 점수·gap) → `## 합의된 결정`(정책 후보·기능 후보·성공기준) → `## 미결 사항` → `## 다음 단계`(planning-format 핸드오프 제안).
- 코드펜스로 리포트 전체를 감싸지 않는다. 진행 로그를 앞세우지 않는다.

# AC Rules (R2 — Acceptance Criteria 검증가능성)

## 용어

- **검증 대상 섹션**: 정책서 5(세부 규칙)·6(상태 처리), 기능설계서 5(기능 동작)·7(예외) **+ 그 안 보조 표(`### N.M ... 보조 표`)** (0.2.4).
- **보조 표 heading 호환**: 0.2.8 clean header(`### N.M ... 보조 표`)와 0.2.4~0.2.7 legacy backlink header(`### N.M ... 보조 표 (§N row M)`)를 모두 보조 표로 인식한다. 일부 중간 산출물의 `(N row M)` backlink도 읽기 호환으로 보조 표 처리한다. legacy header 자체는 planning-review 발견으로 강제하지 않는다.
- **확정 문장**: `[TBD]`가 아닌 단정 표현.

**보조 표 인식 (0.2.4)**: 검증 대상 섹션의 보조 표 본문 확정 문장도 R2 4 sub-category 동일 기준으로 점검한다. 발견 위치 표기는 상위 섹션 + 보조 표 + row 식별(`정책서 5.1 row 3 (보조 표 안)`)을 사용한다. 상위 섹션 단독도 가능하다.

## R2.1 4 sub-category

| 카테고리 | 점검 기준 | 발견 예 |
|---|---|---|
| **정량성** | 비정량 부사(`빨리`·`자주`·`많이`·`대부분`·`즉시`·`천천히`·`종종`·`가끔`·`많은`)가 등장 + 임계값(시간·횟수·비율) 부재 → 발견. | `사용자에게 자주 알림을 보낸다` (간격 부재) |
| **상태** | 상태 전이 규칙이 시작 상태·종료 상태·트리거 모두 적시. 시작이나 트리거 부재 → 발견. | `취소된다` (트리거 부재) |
| **행위자** | 행위 동사(`허용한다`·`차단한다`·`발송한다`·`생성한다`)의 주어가 시스템·사용자 역할 중 하나로 명확. 부재·모호 → 발견. | `결제 정보를 검증한다` (시스템·외부 PG·사용자?) |
| **결과 관찰가능성** | 행위 후 검증 가능한 신호(상태 필드·응답 코드·알림·DB row) 적시. 부재 → 발견. | `요청을 처리한다` (성공 신호?) |

Given-When-Then 변형 — 한 문장 안에 트리거(When)·전제(Given)·결과(Then) 셋이 보이면 4 카테고리 모두 통과.

## R2.2 발견 우선순위

같은 문장이 여러 카테고리에 걸치면 1회만 기록. 우선순위:

1. 정량성
2. 결과 관찰가능성
3. 행위자
4. 상태

0.2.9 기본 출력에서는 R2 발견에 P0/P1 우선순위를 부여한다. 0.2.10부터 P0/P1 R2 finding 또는 그와 연결된 A* 작업은 관찰 가능한 검증 문장을 포함해야 한다.

| 우선순위 | 적용 기준 |
|---|---|
| P0 | 상태 전이 조건, 자동 처리 조건, 외부 시스템 효과처럼 구현/운영 판정을 결정할 수 없는 경우 |
| P1 | 문장은 구현 가능하지만 테스트 조건·행위자·관찰 결과가 부족해 QA/개발 보강이 필요한 경우 |

R2 발견 ID는 `R2-1`, `R2-2` 형식을 쓴다. P0/P1은 `planning-review` 상단 `최우선 수정 항목` 후보가 된다.

## R2.3 제안 형식

수정 제안은 카테고리별 형태:
- 정량성 → `X 임계값 명시`
- 상태 → `트리거 동사 추가`
- 행위자 → `주어 명시`
- 결과 관찰가능성 → `성공 신호 명시`

## R2.4 P0/P1 검증 문장화 (0.2.10)

P0/P1 finding과 그에 연결된 A* 작업은 최소 1개 이상의 Given/When/Then 또는 동등한 테스트 문장을 포함한다.

권장 형식:

```markdown
- 검증 방법:
  - Given Zone이 Closing Planned이고 WCS 연동 플래그가 ON일 때
  - When 나머지 자동 전환 조건이 모두 충족되어도
  - Then Zone은 Inactive로 전환되지 않고 보류 사유가 기록된다
```

검증 문장 작성 규칙:

- 상태 전이는 시작 상태, 트리거, 종료 상태를 포함한다.
- 데이터 변경은 변경되는 필드와 관찰 가능한 이력 또는 응답을 포함한다.
- 권한은 역할, 허용/차단 행위, 사용자에게 보이는 결과를 포함한다.
- 외부 인터페이스는 외부 시스템명, 참조 플래그/ID, 실패 또는 보류 조건을 포함한다.
- `테스트 작성 가능`, `테스트 케이스 작성 가능`, `체크리스트 작성 가능`처럼 가능 여부만 말하는 문장은 P0/P1 검증 방법으로 인정하지 않는다.
- 관찰 가능한 신호가 부족해 검증 문장을 만들 수 없으면 해당 finding 또는 연결 A*에 `구현/QA 차단` 사유를 붙인다.

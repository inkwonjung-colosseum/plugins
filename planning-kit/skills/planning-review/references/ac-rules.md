# AC Rules (R2 — Acceptance Criteria 검증가능성)

## 용어

- **검증 대상 섹션**: 정책서 §5(세부 규칙)·§6(상태 처리), 기능설계서 §5(기능 동작)·§7(예외) **+ 그 안 sub-§(`### N.M ... 보조 표`)** (0.2.4).
- **확정 문장**: `[TBD]`가 아닌 단정 표현.

**sub-§ 인식 (0.2.4)**: 검증 대상 §의 보조 표(sub-§) 본문 확정 문장도 R2 4 sub-category 동일 기준으로 점검. 발견 위치 표기는 부모 § + sub-§ + row 식별 (`정책서 §5.1 row 3 (보조 표 안)`). 부모 § 단독 가능.

## R2.1 4 sub-category

| 카테고리 | 점검 기준 | 발견 예 |
|---|---|---|
| **정량성** | 비정량 부사(`빨리`·`자주`·`많이`·`대부분`·`즉시`·`천천히`·`종종`·`가끔`·`많은`)가 등장 + 임계값(시간·횟수·비율) 부재 → 발견. | `사용자에게 자주 알림을 보낸다` (간격 부재) |
| **상태** | 상태 전이 규칙이 시작 상태·종료 상태·트리거 모두 적시. 시작이나 트리거 부재 → 발견. | `취소된다` (트리거 부재) |
| **행위자** | 행위 동사(`허용한다`·`차단한다`·`발송한다`·`생성한다`)의 주어가 시스템·사용자 역할 중 하나로 명확. 부재·모호 → 발견. | `결제 정보를 검증한다` (시스템·외부 PG·사용자?) |
| **결과 관찰가능성** | 행위 후 검증 가능한 신호(상태 필드·응답 코드·알림·DB row) 적시. 부재 → 발견. | `요청을 처리한다` (성공 신호?) |

Given-When-Then 변형 — 한 문장 안에 트리거(When)·전제(Given)·결과(Then) 셋이 보이면 4 카테고리 모두 통과.

## R2.2 발견 우선순위

같은 문장이 여러 카테고리에 걸치면 1회만 기록. 우선순위:

1. 정량성
2. 결과 관찰가능성
3. 행위자
4. 상태

## R2.3 제안 형식

수정 제안은 카테고리별 형태:
- 정량성 → `X 임계값 명시`
- 상태 → `트리거 동사 추가`
- 행위자 → `주어 명시`
- 결과 관찰가능성 → `성공 신호 명시`

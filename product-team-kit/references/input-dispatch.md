# Input Dispatch Contract

`plan-draft`와 `plan-format`은 입력을 읽기 전에 이 계약으로 입력 종류를 판정한다. 공통 판정 기준은 하나로 유지하되, 첫 행동은 스킬 책임에 맞게 다르게 적용한다.

## 입력 종류별 첫 행동

| 입력 종류 | 판정 기준 | `plan-draft` 첫 행동 | `plan-format` 첫 행동 | 출처 표기 |
| --- | --- | --- | --- | --- |
| 빈 입력 또는 최소 입력 | 입력이 없거나 기능명/키워드만 있어 저장 가능 조건을 판정하기 어려움 | 기획 정보를 한 번 질문하고, 답변도 없으면 부족 항목으로 저장 보류 | 파일을 만들지 않고 정보 부족 저장 보류를 반환해 `plan-draft`로 유도 | 빈 입력은 `[미정]`, 최소 입력은 `plan-draft`: `사용자 답변`, `plan-format`: `사용자 입력` |
| 순수/직접 텍스트 | 기존 파일/디렉터리 경로로 해석되지 않는 기획 의도, 문제 상황, 회의 메모, AI 대화 결과물, 문서 스크랩 | 사용자 답변 기반으로 시작하고, 로컬 맥락이 필요하면 현재 작업 디렉터리에서 좁게 탐색 | 입력 본문 전체를 원 입력으로 사용 | `plan-draft`: `사용자 답변`, `plan-format`: `사용자 입력` |
| draft artifact input | 입력 파일이 `planning/[안전기능명]--YYYY-MM-DD-HHMMSS/[안전기능명]_기획초안.md` 패턴이거나 파일명과 본문 구조상 `plan-draft` 산출 `_기획초안.md`로 식별됨 | 일반 기존 파일 경로처럼 읽고, 필요한 섹션만 기획 근거로 사용 | `draft-artifact`로 표시하고 파일 내용 전체를 원 입력으로 사용. 부족하면 `rerun-contract.md`의 `format-after-draft-insufficient` terminal hold를 따른다 | `로컬 확인: <파일경로>` |
| 기존 파일 경로 | 입력 전체 또는 따옴표 안 경로가 존재하는 파일 | 해당 파일을 먼저 읽고, 필요한 섹션만 기획 근거로 사용 | 해당 파일만 읽고, 파일 내용 전체를 원 입력으로 사용 | `로컬 확인: <파일경로>` |
| 기존 디렉터리 경로 | 입력 전체 또는 따옴표 안 경로가 존재하는 디렉터리 | 해당 디렉터리 안에서만 후보 파일을 검색 | 디렉터리 전체 탐색 금지. 파일 경로나 본문 입력이 필요하므로 정보 부족 저장 보류 | `plan-draft`: `로컬 확인: <파일경로>`, `plan-format`: `[확인 필요]` |
| 없는 path-like 입력 | `/`, `./`, `../`, 확장자, 또는 경로 구분자를 포함하지만 존재하지 않음 | 파일로 읽지 않는다. 경로 후보는 `경로 확인 필요`로 기록하고, 나머지 문장은 사용자 의도로 처리한다. 저장 가능 조건을 충족하면 저장하고, 부족하면 질문 또는 저장 보류 | 파일로 읽지 않는다. 나머지 텍스트가 저장 가능 조건을 충족하면 그 텍스트만 사용하고, 부족하면 정보 부족 저장 보류 | 경로 후보는 `[확인 필요]`; 나머지 문장은 `plan-draft`: `사용자 답변`, `plan-format`: `사용자 입력` |
| 주제 + 경로 혼합 | 설명 문장 안에 기존 파일/디렉터리 경로가 포함됨 | 경로는 탐색 범위로, 주제 문장은 검색어와 사용자 의도로 사용 | 기존 파일이면 파일을 읽고 주제 문장은 해석 lens로 사용. 기존 디렉터리면 디렉터리 자체는 읽지 않고, 주제 문장이 저장 가능 조건을 충족하면 주제 문장만 원 입력으로 사용 | 주제 문장은 `plan-draft`: `사용자 답변`, `plan-format`: `사용자 입력`; 파일 내용은 `로컬 확인: <파일경로>`; `plan-format`의 디렉터리는 `[확인 필요]` |

## 스킬별 추가 규칙

- `plan-draft` 입력은 기능 아이디어, 문제 상황, 회의 메모, 파일 경로, 로컬 프로젝트 경로, 또는 주제와 경로가 섞인 문장일 수 있다.
- `plan-draft`에서 입력이 거의 없으면 먼저 한 번만 질문한다. 이 질문도 기획 정보를 요청하므로 1라운드로 계산한다.

```text
어떤 기능 또는 업무 문제를 기획 초안으로 정리할까요?
```

- `plan-format`은 제공된 입력을 검증하고 문서화하는 formatter다. 일반 입력이 부족하면 추가 질문 루프를 만들지 않고 `plan-draft`로 보완을 유도한다.
- `plan-format` 입력 파일이 `draft artifact input`이면 저장 위치와 충돌 처리는 `storage-contract.md`를 따르고, 정보 부족 재실행 제어는 `rerun-contract.md`를 따른다.

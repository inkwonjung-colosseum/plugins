# Markers Contract

`plan-draft`, `plan-format`, `plan-review`는 확정 사실, 미정, 가정, 확인 필요, 충돌 후보를 섞지 않는다.

## Marker 정의

- `[미정]`: 결정되지 않은 필수 판단. 빈 칸 전부가 아니라 문서 확정에 영향을 주는 결정사항에만 사용한다.
- `[가정]`: 입력에 없지만 컨텍스트로 명시적으로 추론한 내용. 확정 사실처럼 쓰지 않는다.
- `[확인 필요]`: 결정자 답변이나 후속 확인이 필요한 항목. 이유, 결정 주체, 후속 확인 방법을 함께 남긴다.
- `[충돌 후보]`: 사용자 주장과 로컬 확인 또는 Project Docs SSOT 근거가 실제로 불일치하는 후보. 가능성만으로 붙이지 않는다.

## 표기 구분

`[확인 필요]`와 `확인 필요 질문`은 다른 표기다.

- `[확인 필요]` (괄호 있음): 문서 본문 또는 표 셀에 개별 항목 단위로 붙이는 **inline 마커**. 결정이 쓰이는 위치에 직접 표시한다.
- `확인 필요 질문` (괄호 없음): 출력 템플릿 섹션 헤더와 산문에서 사용하는 **모음 레이블**. `[확인 필요]` 항목들의 집합을 가리킨다. 마커가 아니므로 `[...]`로 쓰지 않는다.

## 공통 규칙

- 사용자가 모르면 `[미정]`으로 남긴다.
- 공백, 무응답, `모름`, `정하지 않음`만 있는 답변은 해당 항목을 `[미정]`으로 기록한다.
- `[충돌 후보]`는 확정 사실로 쓰지 않는다. 사용자 답변과 Project Docs SSOT 근거가 다르면 어느 쪽도 우선 확정하지 않고 충돌 항목, 사용자 주장, 로컬 근거 경로, 후속 확인 방법을 남긴다.
- `[충돌 후보]`는 저장 차단 사유가 아니다. 저장 가능 조건을 충족하면 저장하고 충돌 항목으로 남긴다.

## `plan-draft` 적용

- 사용자 답변 기반: `사용자 답변`
- 로컬 파일 기반: `로컬 확인: <파일경로>`
- 확정 불가: `[미정]`
- 추정 포함: `[가정]`
- 결정자 확인 필요: `[확인 필요]`
- 근거 있는 불일치 후보: `[충돌 후보]`

`[충돌 후보]`는 사용자 주장과 로컬 확인이 다르거나 Project Docs SSOT 근거와 불일치할 때만 사용한다. 가능한 경우 근거 파일 경로, section/path, status signal(`current`/`draft`/`archive`/`deprecated`/`unknown`)을 함께 남긴다.

## `plan-format` 적용

단일 패스이며 반복 질문 루프를 만들지 않는다.

- 확인 필요 질문은 결정자 호출 필요 항목으로만 남긴다.
- inline 계약: 결정이 쓰이는 본문 문장 또는 표 셀에 `[미정]`/`[가정]`을 표시하고 최종 문서에서 제거하지 않는다.
- 문서 끝 색인 계약: 해당 문서에 `[미정]`/`[가정]`이 1건 이상 있으면 최종 문서 끝에 `## 미확정·가정` 섹션을 append하고, 같은 항목을 색인으로 재목록화한다. 0건이면 섹션을 만들지 않는다.
- 화면 출력 계약: 두 문서 전체의 `[미정]`/`[가정]`을 합산해 출력 형식의 `[미확정·가정 항목]` 표에 넣는다. 0건이면 섹션을 생략한다.

# Input Dispatch Contract

`plan-format`은 입력 읽기와 제외 항목 수집을 이 계약으로 판단한다. Python, Node.js, 별도 CLI helper 설치를 전제하지 않는다.

## 입력 종류별 처리

| 입력 종류 | 판정 기준 | 첫 행동 | 출처 표기 |
| --- | --- | --- | --- |
| 빈 입력 또는 최소 입력 | 입력 없음 또는 기능명/키워드만 있음 | 파일 생성 금지. 정보 부족 저장 보류 반환 | `사용자 입력` |
| 직접 텍스트 | 기존 파일/디렉터리 경로로 해석되지 않는 기획 의도, 회의 메모, AI 대화 결과물, 문서 스크랩 | 입력 본문 전체를 원 입력으로 사용 | `사용자 입력` |
| 기존 파일 경로 | 입력 전체 또는 따옴표 안 경로가 존재하는 파일 | 해당 파일의 UTF-8 텍스트를 원 입력으로 사용 | `로컬 확인: <파일경로>` |
| 기존 디렉터리 경로 | 입력 전체 또는 따옴표 안 경로가 존재하는 디렉터리 | 읽을 수 있는 텍스트 파일을 상대경로 오름차순으로 통합 | `로컬 확인: <디렉터리경로> (읽은 텍스트 파일 N개)` |
| 없는 path-like 입력 | `/`, `./`, `../`, 확장자, 또는 경로 구분자를 포함하지만 존재하지 않음 | 경로 오류로 보류하지 않고 입력 문자열 전체를 직접 텍스트 원 입력으로 사용 | `사용자 입력` |
| 주제 + 경로 혼합 | 설명 문장 안에 기존 파일/디렉터리 경로가 포함됨 | 사용자 문장과 기존 파일/디렉터리 내용을 함께 원 입력으로 사용 | `사용자 입력` + `로컬 확인: <경로>` |

## 디렉터리 제한

디렉터리 입력은 무제한으로 읽지 않는다.

- 기본 제외 경로: `.git`, `node_modules`, `planning`, `dist`, `build`, `coverage`, `.cache`, `vendor`, `__pycache__`
- 기본 상한: 파일 100개, 파일당 512KB, 총 2MB
- 바이너리, 권한 오류, UTF-8 디코딩 실패, 상한 초과 파일은 실행을 막지 않고 `[입력 제외 항목]`에 경로와 이유를 남긴다.
- 디렉터리 안의 기존 `_기능설계서.md`, `_정책서.md`는 일반 참고 입력일 뿐 저장 보류 사유가 아니다. 새 산출물은 항상 새 timestamp 폴더에만 저장한다.

## Gate 연결

- 입력 확인 단계는 입력을 읽고 정리할 뿐 변환 가능성을 판단하지 않는다.
- `plan-format`은 원 입력을 기준으로 Gate First를 수행한다.
- Gate First 통과 전에는 저장 폴더 생성이나 파일 쓰기를 하지 않는다.
- 저장 보류 출력에는 부족 항목과 입력 제외 항목만 포함한다. 보강용 입력 템플릿, 재실행 명령 블록, 질문 섹션은 만들지 않는다.
- `planning/` 제외는 넓은 디렉터리 crawl에 적용한다. 사용자가 기존 초안 검토를 요청하면 `plan-review`로 라우팅하고, 재포맷을 명시한 경우에만 참고 입력으로 읽되 새 timestamp 폴더에 저장한다.

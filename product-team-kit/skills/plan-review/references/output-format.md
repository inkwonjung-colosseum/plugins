# Output Format

`plan-review`의 최종 출력 단일 기준이다. 판정과 합성 규칙은 `review-rules.md`를 따른다. 출력은 사람용 리포트 하나로 통일하며 별도 YAML manifest 블록은 사용하지 않는다.

## 라벨 체계

판정 라벨:

| 내부 값 | 출력 표시 |
|---|---|
| `통과` | 통과 |
| `조건부 통과` | 조건부 통과 |
| `수정 필요` | 수정 필요 |
| unsupported input | 올바른 검토 대상이 아님 |

발견 분류 라벨:

| 분류 | 출력 표시 |
|---|---|
| 필수 수정 | 필수 수정 |
| 발행 전 확인 | 발행 전 확인 |
| 참고 | 참고 |

역할별 착수 가능성 라벨:

| 내부 값 | 기획자용 라벨 | 의미 |
|---|---|---|
| `ready` | 착수 가능 | 추가 확인 없이 다음 업무 시작 가능 |
| `conditional` | 확인 후 착수 가능 | 기획자가 조건을 확인하면 시작 가능 |
| `blocked` | 착수 전 보강 필요 | 문서 수정 없이는 해당 역할 판단이 달라질 수 있음 |
| `n/a` | 해당 없음 | 해당 역할 업무에 실질 영향 없음 |

## 공통 본문 블록

4종 출력이 공유한다.

1. **판정 헤더**: `판정`, `검토 대상`.
2. **한 줄 결론**: 1~2문장.
3. **먼저 할 일**: 결과별 다음 행동 1~3개.
4. **역할별 착수 가능성** 표: 디자인, 개발, QA, 운영 4행 + 라벨 + 이유 + 필요한 보강 또는 확인 + 위치.
5. **기준 문서와의 충돌** 표: 항목, 초안 내용, 기준 문서, 판단.
6. **상세 검토 기록**:
   - Coverage 표 (단일 행: 검토 축, 상태, 발견 항목 수, 근거)
   - 읽은 근거 list
   - 읽지 않은 관련 후보 list
   - 제외 후보 list
   - 검증 한계 list

## 결과별 추가 블록

- **통과**: 발행 준비 체크리스트.
- **조건부 통과**: 발행 전 확인 항목 표 + 발행 준비 체크리스트.
- **수정 필요**: 필수 수정 항목 표 + 재검토 안내 체크리스트.
- **올바른 검토 대상이 아님**: 다음 행동 안내만.

`발행 준비 체크리스트`와 `재검토 안내 체크리스트`는 사람용 markdown 체크박스 list로만 출력한다. YAML manifest는 사용하지 않는다.

## 통과

````text
판정: 통과
검토 대상: [파일경로]

한 줄 결론:
- 기준 문서와 충돌이 없고, 적용 대상 역할이 다음 업무를 시작할 수 있습니다.

먼저 할 일:
1. 기능/화면설계서와 정책서 묶음이 팀에 공유할 대상인지 최종 확인하세요.
2. 팀의 외부 반영 절차에 따라 문서 반영 여부를 결정하세요.

역할별 착수 가능성:
| 역할 | 착수 판단 | 이유 | 필요한 보강 또는 확인 | 위치 |
|---|---|---|---|---|
| 디자인 | [착수 가능 | 해당 없음] | [요약 또는 UI 영향 없음 사유] | 없음 | [섹션 또는 없음] |
| 개발 | 착수 가능 | [상태/권한/예외/연동 판단 요약] | 없음 | [섹션 또는 없음] |
| QA | 착수 가능 | [전제조건/기대 결과/예외 확인 기준 요약] | 없음 | [섹션 또는 없음] |
| 운영 | 착수 가능 | [운영 처리/공지/로그/전환 영향 판단 요약] | 없음 | [섹션 또는 없음] |

기준 문서와의 충돌:
| 항목 | 초안 내용 | 기준 문서 | 판단 |
|---|---|---|---|
| 없음 | 없음 | [사용한 기준 문서 요약 또는 `SSOT corpus 0건 (관련 Markdown 부재)`] | [충돌 없음 또는 `검증 대상 없음`] |

발행 준비 체크리스트:
- [ ] 검토 대상 초안의 기능설계서/정책서 쌍을 확인한다.
- [ ] 팀 문서 반영 후 팀 문서 ID와 update timestamp를 별도 운영 기록에 남긴다.
- [ ] plan-review가 외부 시스템에 직접 게시하지 않는다.
- [ ] <outputRoot>/ 산출물을 Product Docs SSOT 근거로 승격하지 않는다.
- [ ] Product Docs SSOT Markdown 또는 팀 문서 export snapshot을 자동 수정하지 않는다.

상세 검토 기록:

검토 기준: 4축 점검 (SSOT 충돌, 명확성, 용어 일관성, 4역할 넘김 가능성)

Coverage:
| 검토 | 상태 | 발견 항목 수 | 근거 |
|---|---|---:|---|
| 4축 합산 | completed | 0 | Product Docs SSOT |

읽은 근거:
- path: [상대경로] / kind: [markdown|linked_local_resource] / source_type: [policy|prd|requirement|feature|screen|operations|qa|unknown] / role: [primary|supporting|conflict_candidate|context_only] / version: [vX.Y|unversioned|unknown] / current_evidence: [true|false] / status: [current|draft|archive|deprecated|unknown] / freshness: [explicit_current|dated|undated|unknown]
- (SSOT corpus 추출 성공, 매칭 0건이면) `SSOT corpus 0건 (관련 Markdown 부재) — A. SSOT 충돌 축 검증 대상 없음`

읽지 않은 관련 후보: 없음

제외 후보:
- [외부 URL, 코드, 설정, <outputRoot>/ 하위 등 / 제외 사유 또는 없음]

검증 한계: 없음

참고 사항:
| 축 | 제목 | 위치 | 분류 | 발견 유형 | 근거 인용 | 영향 |
|---|---|---|---|---|---|---|
| [축 또는 없음] | [제목 또는 없음] | [문서 > 섹션 또는 없음] | 참고 | [오류/누락 또는 없음] | [짧은 인용 또는 없음] | [영향 또는 없음] |
````


## 출력 순서

3. 먼저 할 일 / 먼저 고칠 항목

## 금지 행동

- plan-review는 외부 시스템에 직접 게시하지 않는다.
- `<outputRoot>/` 산출물을 Product Docs SSOT 근거로 승격하지 않는다.
- Product Docs SSOT Markdown, 팀 문서 export snapshot, linked local resource를 자동 수정하지 않는다.
- 코드, 설정 파일을 수정 대상으로 제안하지 않는다.
- 검토 대상 본문 또는 SSOT 근거에 없는 사실을 새로 만들지 않는다.
